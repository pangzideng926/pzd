# Agent Note: 导入 pzd_Workflow 通用规则到项目内，AGENTS.md 合并为统一入口

Status: implemented

## Problem

维护者有一套个人通用规则仓 [pzd_Workflow](https://github.com/pangzideng926/pzd_Workflow)，覆盖需求 → 规格 → 拆票 → 实施验证、worktree 与提交收尾、验证证据分级、日周复盘和知识沉淀。PZD 的 `AGENTS.md` 却是另起炉灶写的，两边出现了三类问题：

- **冲突**：PZD 规则里写着「直接删除」被否记录和被取代的笔记，违反通用规则工作原则硬闸 A2「绝不执行删除，一律移到回收站」。
- **规则落不了地**：[Bot 分工](2026-10-28-bot-division-of-labor.md)规定票用 GitHub Issues、审计结论写在 PR 评论里。但这台机器没有 `gh`，仓库又是私有的，GitHub API 读不到，Bot 实际上无法读票，也无法认领。
- **重复**：「完成只认实际输出」「提交 / 推送 / 合入分开报告」「审查只读」这些规定，通用规则里已有更完整的正文，PZD 又写了一份。

## Decision

### 文件构成

- 通用规则从 pzd_Workflow `a356ac0` 整份导入到项目内，共 35 个文件，与上游逐字节一致：
  - `.ai/`：`规则/`、`模板/`、`知识库/`、`记忆.md`、`工具接入.md`、`工作区导航.md`、`子仓库接入检查.md`
  - `scripts/`、`tests/`：通用规则的可选实现，规则任务不会自动调用它们
- **通用文件不就地修改**：要改先改上游，再整份同步过来。
- PZD 自己的规则只有三个文件，同步上游时不覆盖：
  - `AGENTS.md`
  - `.ai/规则/Bot分工.md`
  - `.ai/规则/决策笔记.md`
- `AGENTS.md` 以上游入口为骨架合并，加上规则来源、项目事实、两份 PZD 专项规则的路由；目标 100 行以内，细则只放链接。`CLAUDE.md` 仍然只有 `@AGENTS.md`。
- 资料根就是本项目：`.ai/记忆.md`、`.ai/知识库/` 导入时是空白模板，写第一条真实内容时替换模板说明。
- 上游的 `README.md` 描述的是规则仓本身，对 PZD 不成立，没有导入。维护者移除了 PZD 的 `README.md` 和 `.editorconfig`，项目入口只保留 `AGENTS.md`。
- `.gitignore` 按 PZD 的目录重写，没有照搬上游：上游是「先忽略一切、再逐个放行」的白名单，放进 PZD 会把以后新增的 `docs/`、`.agents/notes/` 文件全部忽略。新的 `.gitignore` 覆盖凭据、通用规则约定的 `.worktree/`、`.tmp/`、`backups/`、`归档/`、`回收站/`，以及重新实现后会出现的构建产物。

### 规则调整（写在两份 PZD 专项规则里）

- **票**：放在仓库内 `docs/work/<功能标识>/tickets/NN-<短名>.md`，使用通用规则规定的任务头。认领方式是在任务分支上改「主写入者」和「状态」，提交并推送。取代原来的 GitHub Issues。
- **交接与审计结论**：写进票文件，仍然必须包含四项（目标、提交、验证原样输出、遗留）。同一张票只保留最新一次审计结论，不另建审计报告。取代原来的「写在 PR 评论里」。
- **worktree**：位置统一为通用规则约定的 `.worktree/<票号>/`。PZD 更严：实现 Bot 一律进 worktree，即使主工作树是干净的。
- **移除笔记**：按 A2 移到回收站，再提交这次移除，不用 `rm`、`git rm`。
- **必须先写失败测试的清单**：在通用规则基础上增加租户隔离与解析、权限码与数据范围、审批流状态流转、Outbox 投递与幂等。
- **决策笔记与知识库分工**：「为什么这样做」写 `.agents/notes/`，作为 PZD 的 ADR；跨项目可复用的教训写 `.ai/知识库/`。两处不重复。

## Alternatives considered

- **只在 AGENTS.md 里引用本机的 `E:/Eworkspace/pzd_Workflow`，不复制** — 最强理由：符合通用规则 B7「不建立仓库私有的规则副本」，上游一更新，PZD 立即生效，不会出现副本过期。这个方案已经写好、尚未提交时，被维护者改成整份导入。原因是引用方案依赖每台机器都把规则仓克隆在同一个相对位置；换机器、跑 CI 或交给别的 Bot 时，所有指向规则的链接都会失效，只剩项目差异可读。按工作原则 C2，用户当轮的明确指令高于 B7。
- **继续用 GitHub Issues 做票，装上 `gh` 解决访问问题** — 最强理由：Issues 有通知、指派、标签，人看起来最方便，也和 DS-Bot 的做法一致。没选，是因为每个 Bot 会话都要先配好 GitHub CLI 和凭据才能读写票，而硬闸 A4 要求不查看、不输出令牌，逐个会话配置凭据很容易碰到这条线；票放在仓库内，只要能读仓库的 Bot 就能读票，认领状态也随分支一起留在版本历史里。
- **审计结论继续只写在 PR 评论里** — 最强理由：仓库里不会出现任何审计过程，彻底避免之前报告越堆越多的问题。没选，是因为通用规则要求票记录本次交付和验收证据、作为唯一正文，审计结论放在仓库外就和这条冲突。用「只保留最新一次」加「固定四项」限制篇幅，同样能防止堆积。

## Consequences

- **收益**：
  - 仓库自包含：任何机器、任何 Bot 只要拿到仓库就能读到全部规则，不依赖本机目录结构。
  - 不再有和硬闸 A2 冲突的条款，通用流程也不在 PZD 里重复写一遍。
  - 票和认领状态都在仓库里，不依赖 `gh` 或 GitHub 凭据。
- **代价**：
  - 通用规则在 PZD 里是副本，上游更新后不会自动生效，需要手动同步；忘了同步，两边就会悄悄分叉。
  - 「通用文件不就地修改」全靠自觉，没有机器检查。有人在 PZD 里直接改了通用文件，下次同步就会被覆盖，改动丢失。
  - 仓库多了 35 个通用文件，其中 `scripts/`、`tests/` 是 PowerShell 实现，PZD 自己的流程不依赖它们。
  - 票和审计结论回到仓库里，需要靠「只保留最新一次」「固定四项」持续约束篇幅。
- **重访信号**（出现任一情况就重新评估）：
  - 上游 pzd_Workflow 有新提交，而 PZD 的副本还停在 `a356ac0`。
  - 发现 PZD 里的通用文件和上游同版本不一致。
  - 某张票的审计记录超过一屏仍在增长。
  - 维护者决定为 Bot 配置 GitHub 访问。

  ```bash
  rg -n "删" AGENTS.md .ai/规则/Bot分工.md .ai/规则/决策笔记.md
  ```
