# Agent Note: 多 Bot 分工：四个角色、单写入方、四项交接、每个 Bot 独立 git 身份

Status: implemented

## Problem

PZD 由多个 Bot 并行开发，但此前分工没有成文，步骤 1–2 期间暴露了三个问题：

- **多个进程同时写同一个工作树。** 票 13（Platform 入口）的改动还没提交时，另一个进程在同一个 `E:\pzd` 里做仓库清理，这些改动最后随清理一起被丢弃，无法恢复。
- **审计过程挤占仓库。** 测试、审计、复审的过程记录占了约 6800 行文档，同一个结论在 README、交接记录和报告里各写一遍，最后出现了互相矛盾的说法。
- **分不清是谁做的。** 所有提交的作者都是维护者本人，末尾统一挂 AI 署名，从 `git log` 看不出哪一步是实现、哪一步是审计。

不把分工写死，新一轮重新实现时，这三件事还会再发生。

## Decision

`AGENTS.md`「Bot 分工」一节是现行规则，要点如下：

- **四个角色**：维护者（用户本人）、调度 Bot、实现 Bot、审计 Bot。各角色职责和禁止事项见 `AGENTS.md` 的角色表。架构决定和合并到 `main` 只由维护者做。
- **票用 GitHub Issues**，通过留言认领。一张票对应一个分支、一个 PR，分支命名为 `feat|fix|docs|chore/<票号>-<主题>`，从 `main` 拉，同步只用 `git merge main`。
- **一个工作树同一时间只允许一个写入方**：每个实现 Bot 在自己的 `git worktree` 里工作。开工前看到不属于自己的未提交改动，必须停下报告，不许删除或覆盖。
- **交接必须带四项**：目标、commit hash、验证命令和原样输出、遗留问题，缺一项接手方直接退回。
- **审计结论写在 PR 评论里，不进仓库**；仓库里只留决策笔记。
- **每个 Bot 用独立的 git 身份**作为作者和提交者，例如 `PZD-实现Bot-1 <impl-bot-1@pzd.local>`。提交不加任何 `Co-Authored-By` 行，这条规则优先于工具自带的署名设置。

## Alternatives considered

- **作者保持维护者本人，提交末尾加 `Bot-Role:` 和 Bot 的 `Co-Authored-By` 署名** — 最强理由：提交都关联到维护者的 GitHub 账号，会计入贡献图；同时能用 `git log --grep "Bot-Role:"` 按角色筛选。没选，是因为维护者明确选择了每个 Bot 用独立身份。用独立身份，`git log --author` 就能直接按 Bot 筛选，不必依赖每个提交都记得写 trailer。
- **照搬 DS-Bot：作者是提出需求的人，禁止 AI 署名** — 最强理由：责任归属清楚，提交历史里不出现 AI 身份。没选，是因为在 PZD 里，需求几乎都由维护者提出，结果和现在一样看不出哪个提交是实现、哪个是审计，第三个问题没有解决。
- **不分角色，一个 Bot 从实现做到审计** — 最强理由：没有交接成本，也不用协调。没选，是因为自己审自己的提交不算独立验证；而步骤 1–2 里不少缺陷，恰恰是在另一个人独立重跑时才发现的。

## Consequences

- **收益**：
  - 同一时间同一目录只有一个写入方，不会再出现未提交的工作被别人覆盖的情况。
  - 交接内容固定为四项，接手方不用先猜上下文。
  - 仓库只保留决策，不再堆积过程记录。
  - `git log --author="PZD-审计Bot"` 这类命令可以直接按角色查看提交。
- **代价**：
  - Bot 身份的邮箱不对应任何 GitHub 账号，这些提交不会计入维护者的贡献图，GitHub 上也不会显示头像。
  - 每个实现 Bot 都要单独建 worktree 和分支，比直接在主工作树里改多几步。
  - 审计过程只留在 PR 评论里；仓库一旦离开 GitHub，这部分记录就看不到了。
  - 这些规则都没有机器检查，全靠 Bot 遵守，和[决策笔记只靠规则卡控](2026-10-28-agent-notes-rules-only.md)的取舍一致。
- **重访信号**（出现任一情况就重新评估）：
  - 有 Bot 在别人的 worktree 或 `main` 上直接写了代码。
  - 交接评论缺了四项中的任何一项却被接受了。
  - 维护者需要在 GitHub 贡献图上看到这些提交。

## Verification

- `AGENTS.md` 有「Bot 分工」一节，包含角色表、票与认领、单写入方、交接四项、完成与合并五个小节。
- `AGENTS.md`「提交」一节有署名规则，并给出了 `git -c user.name=… -c user.email=… commit` 示例。
- 规则生效之后，`git log --format='%an <%ae>'` 里的 Bot 提交都应该是 `PZD-…Bot` 身份，且提交信息里没有 `Co-Authored-By`。
