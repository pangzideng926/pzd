# db/tenant

租户库的版本化 SQL 放这里：每个租户一个独立库（architecture.md §6.1），**同一套脚本对全部租户库执行**。

## 命名与放置

- 文件名规则同 master 库：`NNNN_简述.sql`，序号全局递增、永不复用、按序号执行。
- 业务表、索引、约束都写在这里；表里**不带 `tenant_id` 列**——隔离靠「一个租户一个库」，不靠行级过滤。
- 不写 `CREATE DATABASE`、不写账号授权：租户库的创建属开通流程（21 号票）。
- 不写任何凭据或真实主机名。

## 执行约定

- **先迁移后部署**（§15.4）：结构先行，代码随后。
- 逐租户执行并记录版本：每个租户库自己记「已应用到第几号」，便于看板与重试（§6.4）。
- 灰度 → 全量：先在少量租户试跑，再全量；**单个租户失败不阻塞其他租户**，失败租户单独标记、单独重试（§15.4 第 3 步）。
- 只做前滚，不提供 down 脚本；破坏性变更走 expand-contract 两段（§15.3）。
- 与 master 库互不引用，不做跨库事务（§3.3）。
