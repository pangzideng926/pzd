# db/master

master 库的版本化 SQL 放这里：租户、套餐、菜单与权限码、Quartz 表等平台级对象。**不含任何业务表**。

## 命名与放置

- 文件名 `NNNN_简述.sql`：4 位十进制序号 + 下划线 + 小写英文简述，例如 `0001_create_package.sql`。
- 序号**全局递增、永不复用**，删除的业务不再重排序号；执行顺序只看序号，不看时间。
- 一个文件对应一次逻辑变更，不把互不相干的建表塞进同一个文件。
- 文件内**不写** `CREATE DATABASE` / `USE` / 账号授权，库与实例的创建属运维或开通流程（21 号票）。
- 不写任何凭据、真实主机名或口令。

## 执行约定

- **只做前滚**：不提供 down 脚本；出错靠新脚本修正。
- **先迁移后部署**（architecture.md §15.4）：数据库结构先行，应用代码随后发布。
- 破坏性变更走 expand-contract 两段：本版本加新结构并双写，下一版本才删旧的（§15.3）。
- 一次迁移要么整体成功，要么整体回滚，由执行器负责；单个迁移文件不自己开事务边界。
- 与租户库**互不引用**，不写跨库查询、不做跨库事务（§3.3 事务边界）。

## 未定项

- 迁移执行器（DbUp 或自研）由维护者拍板（见 [consensus.md](../../docs/work/pzd-v1/consensus.md) §4 待决 2）；本文件只约束「放哪、叫什么、什么顺序」，换执行器不影响这些规则。
- 具体表结构在 17、18、19 号票落地，本目录此刻不含 SQL。
