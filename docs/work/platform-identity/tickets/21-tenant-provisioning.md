# 21 租户开通流程（分步可重试）

## 目标

开通一个租户是分步任务：建库 → 建最小权限账号 → 迁移 → 初始化管理员/角色/字典/默认流程 → 标记可用；每步可重试，单租户失败不阻塞其他。

## 需求依据

- [architecture.md](../../../architecture.md) §6.3
- [spec.md](../spec.md) AC-03
- 拆分依据：[consensus.md](../../pzd-v1/consensus.md) M3.3

## 范围与非范围

- 做：开通任务编排（每步独立事务、状态落库、失败原因可见、重试只补失败步）、建库与建账号、调用迁移执行入口（22 号票或临时占位）、初始化管理员与角色。
- 不做：不做租户开通界面（期外，本票只用 API/命令触发）；不做计费；不做默认流程初始化（M7 期外，留空步骤并标记跳过）。

## 步骤

1. 定义步骤序列与每步产物记录。
2. 实现每步幂等与重试（已成功步骤不重跑）。

4. 集成测试：故意让第 3 步失败 → 该租户标记失败、其他租户成功 → 修复后重试只跑第 3 步及之后。

## 验收标准

- [ ] 开通成功后租户状态为「可用」，各步产物有记录。
- [ ] 某步失败时租户状态为「开通中 + 失败原因」，其他租户不受影响。
- [ ] 重试只执行失败步及后续步，已成功步骤不重复执行。
- [ ] 全过程无明文密码出现在日志或库里。

## 验证入口

```bash
dotnet test tests/Pzd.IntegrationTests --filter Provisioning
```

证据按 L1 记到本票：完整命令、真实退出码、关键输出行、被测 SHA。未运行就写「未运行」，不写成通过。

**假绿防线**：用 `--filter` 时，测试类名必须与 filter 的字面一致；证据里必须贴出实际通过的用例数（>0）。跑出 `0 tests` 的退出码 0 一律按失败处理，不算通过。

**环境性 `0 tests`**（不算假绿，但也不等于通过）：若原因是环境限制——例如沙箱拒绝命名管道，.NET MTP 连不回宿主，报 `UnauthorizedAccessException ... NamedPipeClientStream` 并显示 `总计: 0`——证据里必须同时给出四项：①错误原文与真实退出码；②替代执行方式的实际结果（如直接运行测试 exe）；③明确写「`dotnet test` 本体未运行，需在无管道限制的环境补跑一次」；④剩余风险写进遗留。缺一项就按「未运行」处理，不得写成通过。
