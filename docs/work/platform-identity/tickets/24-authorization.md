# 24 授权模型：权限码、数据范围与缓存失效

## 目标

端点声明权限码即可保护；角色带数据范围；权限变更立刻生效；租户分配受套餐上限约束。

## 需求依据

- [architecture.md](../../../architecture.md) §7.2
- [spec.md](../spec.md) AC-09、AC-10
- 拆分依据：[consensus.md](../../pzd-v1/consensus.md) M3.6

## 范围与非范围

- 做：用户—角色—权限码与数据范围五档、`RequirePermission` 策略提供者、权限缓存（key 含租户与用户）+ 领域事件失效、套餐上限校验、数据范围 QueryFilter 追加条件（依赖 20 号票的最小组织骨架）。
- 不做：不做权限管理界面（期外）；不做字段级权限；不做跨租户数据授权。

1. **先写失败测试**：无权限码应 403；数据范围「仅本人」应只返回本人。

3. 实现权限缓存与领域事件失效。
4. 实现数据范围过滤（四档可测；「自定义」留接口位）。

## 验收标准

- [ ] 无权限码访问受保护端点 403。
- [ ] 授予权限码后无需重新登录即可访问（缓存已失效）。
- [ ] 数据范围「全部」返回本租户全部，「仅本人」只返回本人，两者都看不到他租户数据。
- [ ] 分配超套餐权限码被拒绝（422）。
- [ ] 权限缓存 key 含租户与用户。

## 验证入口

```bash
dotnet test tests/Pzd.IntegrationTests --filter Authorization
```

证据按 L1 记到本票：完整命令、真实退出码、关键输出行、被测 SHA。未运行就写「未运行」，不写成通过。

**假绿防线**：用 `--filter` 时，测试类名必须与 filter 的字面一致；证据里必须贴出实际通过的用例数（>0）。跑出 `0 tests` 的退出码 0 一律按失败处理，不算通过。

**环境性 `0 tests`**（不算假绿，但也不等于通过）：若原因是环境限制——例如沙箱拒绝命名管道，.NET MTP 连不回宿主，报 `UnauthorizedAccessException ... NamedPipeClientStream` 并显示 `总计: 0`——证据里必须同时给出四项：①错误原文与真实退出码；②替代执行方式的实际结果（如直接运行测试 exe）；③明确写「`dotnet test` 本体未运行，需在无管道限制的环境补跑一次」；④剩余风险写进遗留。缺一项就按「未运行」处理，不得写成通过。
