# 25 /api/me：用户信息 + 权限码 + 菜单树

## 目标

前端外壳只需要一个端点就知道「我是谁、我能干什么、我能看到哪些菜单」。

## 需求依据

- [architecture.md](../../../architecture.md) §7.2
- [spec.md](../spec.md) AC-08
- 拆分依据：[consensus.md](../../pzd-v1/consensus.md) M3.7

## 范围与非范围

- 做：`GET /api/me`：用户信息（Id/名称/部门/角色）、权限码数组、按权限过滤后的菜单树；未登录 401。
- 不做：不做用户资料编辑；不做多租户切换；不做菜单权限管理。

## 责任文件范围（认领时在群里先说清）

`src/Pzd.Identity/Endpoints/MeEndpoint.cs`、`src/Pzd.Identity/Application/Queries/MeQuery.cs`、`tests/Pzd.IntegrationTests/MeTests.cs`。

## 关键接口与依赖

- 前置票：24、19
- 对外契约：响应结构被 26、27、29 号票依赖（字段名固定，改动须通知前端三方）。

## 步骤

1. 定义响应 DTO 并写进本票（供前端对齐）。
2. 实现查询：用户 + 角色 → 权限码集合 → 菜单过滤。
3. 集成测试：无权限账号的菜单项减少；未登录 401。
4. 贴真实 JSON 示例（脱敏）。

## 验收标准

- [ ] 未登录 401。
- [ ] 登录后返回用户信息、权限码数组、菜单树。
- [ ] 菜单按权限码过滤，无权限的菜单不出现。
- [ ] 响应用例贴在本票，前端照此实现。

## 验证入口

```bash
dotnet test tests/Pzd.IntegrationTests --filter Me
```

证据按 L1 记到本票：完整命令、真实退出码、关键输出行、被测 SHA。未运行就写「未运行」，不写成通过。

**假绿防线**：用 `--filter` 时，测试类名必须与 filter 的字面一致；证据里必须贴出实际通过的用例数（>0）。跑出 `0 tests` 的退出码 0 一律按失败处理，不算通过。
