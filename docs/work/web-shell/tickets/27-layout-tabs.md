# 27 侧边栏 + 多页签布局与菜单过滤

## 目标

登录后看到按权限过滤的菜单；多页签只做导航，刷新后仍停在原页签。

## 需求依据

- [architecture.md](../../../architecture.md) §14.2、§14.4
- [spec.md](../spec.md) AC-02、AC-04
- 拆分依据：[consensus.md](../../pzd-v1/consensus.md) M4.2

## 范围与非范围

- 做：侧边栏（按 `/api/me` 菜单树渲染）、多页签（打开/切换/关闭、当前页签持久化）、不实现路由级 KeepAlive、页头连接状态位（占位）。
- 不做：不做主题切换、不做面包屑以外的复杂导航、不做 KeepAlive。

## 责任文件范围（认领时在群里先说清）

`apps/web/app/components/layout/**`、`apps/web/app/routes/_app.tsx`。不碰 `_auth`。

## 关键接口与依赖

- 前置票：26
- 对外契约：页签状态存储位置（sessionStorage 或 URL）在此定型，供 33 号票页面复用。

## 步骤

1. 渲染侧边栏菜单树并做权限过滤。
2. 实现页签打开/切换/关闭。
3. 刷新后恢复到当前页签与筛选条件（URL 承载）。
4. 手工验证步骤与结果贴票。

## 验收标准

- [ ] 侧边栏只显示有权限的菜单项。
- [ ] 打开两个页面形成两个页签，切换回原页签筛选条件仍在。
- [ ] 刷新后停在原页签。
- [ ] 无路由级 KeepAlive（切换不保留组件内部状态，只靠 URL 与 Query 缓存）。

## 验证入口

```bash
pnpm --filter web build
pnpm --filter web dev（手工验证）
```

证据按 L1 记到本票：完整命令、真实退出码、关键输出行、被测 SHA。未运行就写「未运行」，不写成通过。

**假绿防线**：用 `--filter` 时，测试类名必须与 filter 的字面一致；证据里必须贴出实际通过的用例数（>0）。跑出 `0 tests` 的退出码 0 一律按失败处理，不算通过。

**环境性 `0 tests`**（不算假绿，但也不等于通过）：若原因是环境限制——例如沙箱拒绝命名管道，.NET MTP 连不回宿主，报 `UnauthorizedAccessException ... NamedPipeClientStream` 并显示 `总计: 0`——证据里必须同时给出四项：①错误原文与真实退出码；②替代执行方式的实际结果（如直接运行测试 exe）；③明确写「`dotnet test` 本体未运行，需在无管道限制的环境补跑一次」；④剩余风险写进遗留。缺一项就按「未运行」处理，不得写成通过。
