# web-shell 规格：前端外壳（M4）

> 基线：2026-10-29（v1）　作者：老何
> 需求依据：[architecture.md](../../architecture.md) §8.5、§10.5、§14.1–§14.4、§15.2
> 拆分依据：[consensus.md](../pzd-v1/consensus.md) M4（M4.1–M4.6）

## 1. 问题

前端目前只有一个模板空壳。后端已经能登录、能返回权限码与菜单，但用户还没有地方登录、没有侧边栏与页签、没有统一的错误处理，也拿不到类型安全的接口客户端。每个页面如果各自处理 401/403/409，界面行为会各不相同。

## 2. 方案

做登录页 + 受保护区路由骨架、侧边栏与多页签布局、orval 生成的请求层与统一错误 mutator、按钮级权限与字典渲染、SignalR 客户端封装、版本更新检测。出口是「登录后看到按权限过滤的菜单」。

## 3. 用户故事

1. 作为租户管理员，我想在登录页输入账号密码后进入后台，以便开始工作。
2. 作为未登录访客，我想访问内部地址时被跳到登录页并在登录后回到原页面，以便不用手动找回去。
3. 作为租户管理员，我想侧边栏只显示我有权限的菜单，以便不点进 403 页面。
4. 作为租户管理员，我想打开多个页面后能在页签之间切换，刷新后仍停在原来那个，以便不丢工作现场。
5. 作为租户管理员，我想表单校验错误直接显示在对应字段下，以便知道改哪里。
6. 作为租户管理员，我想会话过期时被带回登录页且能回到原来页面，以便不丢输入。
7. 作为租户管理员，我想看到连接状态提示，以便知道实时推送是否正常。
8. 作为租户管理员，我想系统发布新版本时收到提示并可刷新，以便用上新功能。
9. 作为租户管理员，我想强制更新时看到明确对话框，以便知道必须刷新才能继续。
10. 作为实现 Bot，我想接口客户端由 openapi 生成，以便后端改字段时前端编译就报错。
11. 作为实现 Bot，我想权限判断有 `<Can>` 和 `usePermission()`，以便不用每个页面自己拼字符串。
12. 作为实现 Bot，我想字典有统一 hook，以便同一字典在各页面渲染一致。
13. 作为实现 Bot，我想每个路由有 ErrorBoundary，以便单个页面炸了不会整站白屏。

## 4. 实现决策

- 路由由前端定义（`routes.ts`），分 `_auth`（登录、忘记密码）与 `_app`（侧边栏 + 多页签）；`_app` 用 `clientLoader` 请求 `/api/me`，未登录 redirect 并带 `redirect` 参数。**不做后端下发动态路由**。
- 多页签只做导航，不做路由级 KeepAlive；页面状态靠 URL search params 与 TanStack Query 缓存恢复。
- 列表统一 TanStack Table + shadcn data-table；**分页 / 排序 / 筛选状态放 URL**。
- 表单 react-hook-form + zod（schema 来自 orval）；后端 ProblemDetails 的 `errors` 通过 `setError` 映射到字段。
- 请求层：`packages/api` 的 orval 自定义 mutator 统一注入 CSRF 头与版本头，并统一拦截：401 → 跳登录（带 redirect）；403 → 无权限提示；400/422 → 字段错误；409 → 「数据已被修改，请刷新」；426 → 强制刷新对话框；503 `Tenant.Upgrading` → 升级中页面；500 → 提示并附 traceId。
- 每个路由配 ErrorBoundary 兜住 loader 错误。
- 实时：`packages/realtime` 封装 `withAutomaticReconnect()`、`useHubEvent`；重连后统一失效关键查询（不做逐消息同步）。
- 版本检测四路并行：`version.json` 轮询、`visibilitychange` 时检查、响应头 `X-App-Build`、SignalR 通知；普通提示可稍后刷新，强制更新必须刷新；多标签用 BroadcastChannel 同步；`vite:preloadError` 兜底；静态资源缓存头与旧 assets 保留期由 31 号票明确写死。
- 约束：外壳不写业务页面；user-management 页面的具体表格列由 33 号票决定。

## 5. 测试决策

- 前端单测只覆盖有分支的逻辑：权限判断 `<Can>`、错误映射函数、版本比较函数。不测组件样式与快照。
- 路由守卫与菜单过滤用 E2E（Playwright，35 号票建立基线）覆盖，不用单测模拟 router。
- 错误映射的代表性正反例：422 带 `errors` 时字段级提示（正例）；422 无 `errors` 时落到页面级提示而不是静默（反例）。
- 版本检测的代表性正反例：`version.json` 版本变化触发提示（正例）；网络失败时静默重试不弹错误（反例）。

## 6. 非目标

- 不做业务页面（用户管理在 33 号票）。
- 不做部门、字典、任务管理等维护界面（原 M6，期外）。
- 不做主题切换、国际化、移动端适配（多语言在 §17 期外）。
- 不做前端错误上报接口（原 M6.9，期外）。

## 7. 验收标准

- **AC-01** 未登录访问 `_app` 下任意路由被重定向到登录页；登录成功后回到原路由。
- **AC-02** 登录后侧边栏只出现当前用户有权限的菜单项；直接访问无权限路由不渲染页面内容。
- **AC-03** `<Can permission="...">` 在无权限时不渲染子节点；`usePermission()` 返回一致结果。
- **AC-04** 打开两个页面形成两个页签，切换回到原页签时筛选条件仍在（URL 恢复）；刷新后仍停在当前页签。
- **AC-05** 后端返回 400/422 带 `errors` 时，表单对应字段出现错误提示且不弹全局错误条。
- **AC-06** 401 时跳登录页并带 `redirect`；403 提示无权限；409 提示刷新；500 展示 traceId。
- **AC-07** `pnpm --filter web build` 成功，且接口客户端由 `openapi.json` 生成（改后端 DTO 字段后前端编译报错可证明）。
- **AC-08** SignalR 断线后自动重连，重连成功显示「已连接」并触发关键查询失效。
- **AC-09** `version.json` 版本变化后出现更新提示；点刷新后加载新构建；多标签页同时收到提示（BroadcastChannel）。
- **AC-10** 静态资源加载失败触发 `vite:preloadError` 兜底（整页刷新）而不是白屏。
