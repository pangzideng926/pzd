# 35 E2E 基线（Playwright：登录 / 权限 / 增删改查）

## 目标

把标杆链路固化成一键回归，后续改动弄坏链路时立刻被发现。

## 需求依据

- [architecture.md](../../../architecture.md) §16.1
- [spec.md](../spec.md) AC-10
- 拆分依据：[consensus.md](../../pzd-v1/consensus.md) M5.4

## 范围与非范围

- 做：Playwright 工程与一条命令；用例：登录 → 看到菜单 → 新建用户 → 列表可见 → 编辑 → 删除 → 列表消失；无权限账号看不到菜单与按钮；测试租户与账号的初始化脚本（不写死密码，从环境变量取）。
- 不做：不做视觉回归、不做跨浏览器矩阵（V1 只跑 Chromium）、不测期外页面。

## 责任文件范围（认领时在群里先说清）

`apps/web/e2e/**`、根 `package.json` 加 `e2e` 脚本、测试数据初始化脚本。不碰业务源码。

## 验收标准

- [ ] `pnpm e2e` 一条命令跑通，退出码 0。
- [ ] 覆盖登录、菜单过滤、增删改查、无权限四类。
- [ ] 测试账号密码来自环境变量，仓库中无明文。
- [ ] 失败时留下截图与 trace。

## 验证入口

```bash
pnpm e2e
```

证据按 L1 记到本票：完整命令、真实退出码、关键输出行、被测 SHA。未运行就写「未运行」，不写成通过。

**假绿防线**：用 `--filter` 时，测试类名必须与 filter 的字面一致；证据里必须贴出实际通过的用例数（>0）。跑出 `0 tests` 的退出码 0 一律按失败处理，不算通过。

**环境性 `0 tests`**（不算假绿，但也不等于通过）：若原因是环境限制——例如沙箱拒绝命名管道，.NET MTP 连不回宿主，报 `UnauthorizedAccessException ... NamedPipeClientStream` 并显示 `总计: 0`——证据里必须同时给出四项：①错误原文与真实退出码；②替代执行方式的实际结果（如直接运行测试 exe）；③明确写「`dotnet test` 本体未运行，需在无管道限制的环境补跑一次」；④剩余风险写进遗留。缺一项就按「未运行」处理，不得写成通过。
