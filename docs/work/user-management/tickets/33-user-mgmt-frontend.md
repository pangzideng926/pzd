# 33 用户管理前端（列表 + 表单 + 权限）

## 目标

一个真实业务页面，示范列表与表单的标准写法：筛选/排序/分页进 URL、错误映射字段、按钮按权限显示。

## 需求依据

- [architecture.md](../../../architecture.md) §14.3
- [spec.md](../spec.md) AC-01、AC-07
- 拆分依据：[consensus.md](../../pzd-v1/consensus.md) M5.2

## 范围与非范围

- 做：用户列表（TanStack Table + data-table，URL 承载状态）、新建/编辑表单（react-hook-form + zod，后端 `errors` 映射字段）、停用/删除二次确认、按钮用 `<Can>` 控制、部门选择器接 20 号票的 `IOrgQuery`。
- 不做：不做批量操作、不做导入导出、不做密码策略配置、不做回收站。

## 责任文件范围（认领时在群里先说清）

`apps/web/app/routes/_app/system/user/**`、必要时在 `apps/web/app/components` 加可复用表格封装。不碰 `packages/api` 生成产物（只消费）。

## 关键接口与依赖

- 前置票：29、32
- 对外契约：本页面的组件组织方式被 34 号票写成前端页面结构约定。

## 步骤

1. 列表页：URL 状态、分页排序筛选。
2. 表单页/抽屉：zod 校验与后端错误映射。
3. 按权限显示按钮，二次确认接删除/停用。
4. 手工验证 + 单测（表单校验映射）。

## 验收标准

- [ ] 列表筛选/排序/分页变化后 URL 同步，刷新可复现。
- [ ] 新建重名用户名时错误显示在用户名字段下，不弹全局错误。
- [ ] 无删除权限的账号看不到删除按钮。
- [ ] 停用与删除都有二次确认。
- [ ] 部门选择器能取到部门数据（20 号票未就绪时降级为文本输入并在遗留写明）。

## 验证入口

```bash
pnpm --filter web build
pnpm --filter web test
pnpm --filter web dev（手工验证步骤贴票）
```

证据按 L1 记到本票：完整命令、真实退出码、关键输出行、被测 SHA。未运行就写「未运行」，不写成通过。

**假绿防线**：用 `--filter` 时，测试类名必须与 filter 的字面一致；证据里必须贴出实际通过的用例数（>0）。跑出 `0 tests` 的退出码 0 一律按失败处理，不算通过。
