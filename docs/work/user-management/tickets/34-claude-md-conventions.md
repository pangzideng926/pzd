# 34 CLAUDE.md 工程约定定型

## 目标

把标杆模块里形成的约定固化下来，后面接业务模块时不再各人自己发明。

## 需求依据

- [architecture.md](../../../architecture.md) §16.2
- [spec.md](../spec.md) AC-09
- 拆分依据：[consensus.md](../../pzd-v1/consensus.md) M5.3

## 范围与非范围

- 做：`CLAUDE.md`：命名（聚合/命令/查询/DTO）、分层与目录、错误码与 `Errors` 类写法、权限码格式、前端页面结构、测试放置与命名、提交信息格式。每条约定附一个指向标杆代码的实际例子。
- 不做：不改 `.ai/` 下导入自上游的通用规则；不复制 architecture.md 正文，只写可执行约定并引用章节号。

## 责任文件范围（认领时在群里先说清）

新建 `CLAUDE.md`（根目录）。不碰 `.ai/规则/` 与 `docs/architecture.md`。

## 关键接口与依赖

- 前置票：32、33
- 对外契约：M6 及以后所有模块开发的前置约定来源。

## 步骤

1. 从 32、33 号票的实际代码归纳约定，逐条给例子。
2. 与 architecture.md 冲突处只引用不重述。
3. 抽查三条约定与代码一致（贴抽查记录）。
4. 让一名未参与本模块的开发按 `CLAUDE.md` 复述一遍，记录歧义点并修正。

## 验收标准

- [ ] `CLAUDE.md` 覆盖命名、分层、错误码、权限码、前端页面结构、测试放置六项。
- [ ] 每条约定都有指向标杆代码的例子。
- [ ] 抽查三处与代码一致。
- [ ] 无与 architecture.md 矛盾的表述。

## 验证入口

```bash
人工审查（记录抽查的三处文件与行号）
```
