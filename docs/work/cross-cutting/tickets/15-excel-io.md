# 15 Excel 导入导出（流式 + 异步大文件）

## 目标

小数据量流式导出/导入可用；大数据量走异步生成，完成后通知下载。

## 需求依据

- [architecture.md](../../../architecture.md) §13
- [spec.md](../spec.md) AC-11
- 拆分依据：[consensus.md](../../pzd-v1/consensus.md) M2.11

## 范围与非范围

- 做：MiniExcel 流式导入导出封装；大数据量异步生成 → 对象存储 → 通过 Outbox/通知接口发出下载通知（SignalR 端在 30 号票接通）。
- 不做：不做前端下载界面；不做导入模板设计器；不做 Excel 公式计算。

## 责任文件范围（认领时在群里先说清）

新建 `src/Pzd.Infrastructure/Excel/**`、`tests/Pzd.IntegrationTests/Excel/**`。不碰 `src/Pzd.Infrastructure/Storage` 的实现（只调接口）。

## 关键接口与依赖

- 前置票：14、08
- 对外契约：导入结果形状（成功行数/失败行 + 原因）固定，供业务模块复用。

## 步骤

1. 封装流式导出与导入。
2. 实现阈值切换：超过配置行数转异步。
3. 异步生成写对象存储并发通知。
4. 测试：1 万行导入导出内存不爆；失败行能定位到行号与原因。

## 验收标准

- [ ] 流式导出 1 万行不出现全量加载内存。
- [ ] 导入失败返回行号与原因，不整批静默丢弃。
- [ ] 超过阈值自动转异步生成并落到对象存储。
- [ ] 生成完成发出下载通知（SignalR 未接通时记录为遗留）。

## 验证入口

```bash
dotnet test tests/Pzd.IntegrationTests --filter Excel
```

证据按 L1 记到本票：完整命令、真实退出码、关键输出行、被测 SHA。未运行就写「未运行」，不写成通过。

**假绿防线**：用 `--filter` 时，测试类名必须与 filter 的字面一致；证据里必须贴出实际通过的用例数（>0）。跑出 `0 tests` 的退出码 0 一律按失败处理，不算通过。
