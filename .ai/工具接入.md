# 工具接入说明

本文件是用户选择具体工具或实现后按需读取的可选说明，不是通用流程、规则验收或普通本地操作的前置要求。仅按已授权范围和当前环境实际能力使用；不因读取规则而自动安装、调用工具、启用钩子或修改配置。未选择或无法使用这些实现时，可用其他合规方法取得必要证据；缺少必要证据仍须标明未验证。

工具入口复用 [AGENTS.md](../AGENTS.md)，通用方法以对应专项正文为准。辅助脚本随本仓 `scripts/` 分发；外部 MCP 与技能未随本仓分发，选用时才核对其安装、来源版本和可用能力。不提交本机配置、凭据或真实运行记录。

## 复盘快照（可选）

通用范围、覆盖和处置要求见[每日复盘](规则/每日复盘.md)。选择 [Get-ReviewSnapshot.ps1](../scripts/Get-ReviewSnapshot.ps1) 时，在 PowerShell 7.3+ 中调用；路径和时间替换为已确认的实际值，目标引用不得按名称猜测：

```powershell
pwsh -NoProfile -NonInteractive -File '<规则仓库>/scripts/Get-ReviewSnapshot.ps1' -Repository '<仓库根目录绝对路径>' -TargetRef '<目标引用>' -BaselineSha '<上次已覆盖截止SHA>' -Since '<开始时刻>'
```

- 需要 Git 2.40+。没有已确认基线时省略 `BaselineSha`，不能填造历史 SHA。选择该实现后，以本次输出 JSON 形成提交覆盖清单，不在同一记录内另行手算一份冲突清单。
- 输出包含截止 SHA、dirty 状态、第一父链进入事件、合并带入提交（含旧日期提交）、按完整 SHA 去重的 `coverage.toReview`、`coverage.innerMerges`、本快照内的 patch-id 等价补丁及 `limitations`。退出码 0 表示快照完成，2 表示未完成，1 表示参数错误。
- 有基线时按“基线..截止”计算。`enteredInWindow` 依据本地 reflog 进入时间；没有 reflog 时只有 `committedInWindow`（提交时间），不能代表进入时间。无基线、基线对象缺失或不是祖先时按时间窗口列候选并写入限制；零候选不能证明远端零合入。
- 同日以前次截止 SHA 为基线得到本轮增量；保留当天累计覆盖与本轮增量的区别。脚本只做本地快照，不 fetch，不证明远端完整性；需要远端证据时按本次授权另行核验。
- 脚本不执行仓库配置的 textconv、diff 驱动或 clean/smudge filter；`.git/info/attributes` 配置了 filter 时跳过已跟踪文件的修改检测，`dirty.known=false`，按未知记录。
- 对 `coverage.toReview` 逐项读取实际差异，合并检查包括 `innerMerges`。patch-id 仅提供补丁对应线索；跨快照关联已有事故时可对事故 SHA 单独计算 `git patch-id --stable` 比较，不能只凭补丁等价推定根因相同、集成有效或证据已审查。

## 错题本结构检查（可选）

通用计次、证据及修复要求见[每日复盘的错题本维护](规则/每日复盘.md#错题本维护)。选择 [Test-Lessons.ps1](../scripts/Test-Lessons.ps1) 时，`Root` 是实际资料根，`File` 是相对该根的 Markdown 路径；在 PowerShell 中可传显式数组，不因此扫描整个知识库：

```powershell
& '<规则仓库>/scripts/Test-Lessons.ps1' -Root '<资料根绝对路径>' -File '.ai/知识库/AI错题本.md'
```

- 输出重复编号、静态缺证据、本地链接及 Seen 账面核对结果；不修改文件、不联网、不读取引用目标正文，只有目标也在 `File` 中才核对其锚点。根外引用不访问；不能判断的引用、格式与事故完整性列入 `notChecked` 或条目的 unknown，不当作通过或错误。
- 拒绝越界输入、链接／目录连接、硬链接和超过 1 MiB 的选定文件。文件指纹对应本次读取内容，不是跨文件原子快照；写入前仍须重核并行变化。
- 识别围栏与 HTML 注释外的 `## AI-数字：` 条目、行内 Markdown 链接、ATX 标题与简单显式 HTML 锚点；其他 AI 编号与引用式链接明确列未检查，不完整模拟 Markdown 渲染器。旧事故、来源或验证说明仅作为待核验线索，不能因缺少新版字段就断言没有证据。
- 退出码 0 仅表示检查完成，仍可能有 `findings`；2 表示输入或读取未完成，参数绑定失败保持非零。分别核对 `complete`、`findings`、`notChecked` 与条目状态。
- 只有 `事故 ID 完整：是` 时才比较唯一 ID 数量与 Seen；账面一致不证明事故独立性或证据真实性。旧格式缺字段不得据此批量重写；人工确认发现后的处理仍按[自动修复与入库](规则/每日复盘.md#自动修复与入库)执行。

## 知识检索（可选）

通用检索、来源核实和使用边界见[协作与知识](规则/协作与知识.md)。选择 [Search-Knowledge.ps1](../scripts/Search-Knowledge.ps1) 时，以项目／业务词和症状／字段组成 2～3 个关键词，在 PowerShell 中按数组传入：

```powershell
& '<规则仓库>/scripts/Search-Knowledge.ps1' -Root '<资料根绝对路径>/.ai/知识库' -Keyword @('<词1>', '<词2>')
```

- 结果按命中关键词数排序，含条目 ID、位置、状态、证据、`ReviewReasons` 与 `UseAdvice`（candidate／verify-first／history-only）；退出码 0 表示完成，2 表示未完成，1 表示参数错误。
- 错题本模板没有“状态／最后核验”字段，其条目固定为 verify-first，引用前核对原证据。先看少量结果，再读取命中条目全文和必要来源。
- `UseAdvice`／`ReviewReasons` 仅依据元数据和明确期限提示复核原因，不验证来源内容或当前环境，也不提供执行授权。
- 脚本只读文件；终端支持按命令选择沙箱时使用只读模式。脚本或终端不可用时，可在已授权范围内使用原生文本检索并读取完整条目，说明使用的方法与限制；不提升到全权限、不改 ACL 或全局权限。

## 通用规则预检（可选）

通用维护职责、源白名单和发布边界见[规则同步](规则/规则同步.md)。选择 [Test-RuleSync.ps1](../scripts/Test-RuleSync.ps1) 时，在 PowerShell 7.3+ 中传入真实绝对路径；从任何目录调用都不在源工作区根执行 Git：

```powershell
pwsh -NoProfile -File '<规则仓库>/scripts/Test-RuleSync.ps1' -SourceRoot '<本地工作区>' -RepositoryRoot '<规则仓库>'
```

- 脚本只输出 JSON，无写入或网络选项。退出码 0 表示预检完成（仍可能有 findings），2 表示未完成；两者均不表示可发布。`checked`、`findings`、`notChecked` 分别对应已检查、需人工判断和未检查；`comparisons` 仅忽略换行差异，引用入口也会显示 different，需结合迁移状态理解。
- 源检查路径只从[白名单标记表](规则/规则同步.md#源内容检查白名单)读取；本仓可检查和发布的目标路径由脚本精确限定，扩展须代码审查。输出两侧状态与规范化 SHA256，不输出原文或命中的敏感值；拒绝跟随符号链接／目录连接，单文件大于 1 MiB 跳过并记录。
- 有限检查密钥格式、疑似口令赋值、本机路径和私网地址，不能识别所有客户名或语义泄露；零命中不能替代人工审核。
- 本仓 Markdown 只检查允许范围内的行内相对链接及 ATX 标题锚点；未知锚点或范围外引用需另行核对，不联网验证，源文档项目链接不展开。
- Git 子进程隔离继承的 Git 环境与全局配置，禁用可选写锁、过滤器配置、替换对象和自动 lazy fetch；只支持普通检出目录，拒绝 include、外部 worktree／对象库、浅历史及已检查元数据路径的链接。工作区仅用 stat 元数据查询，可能多报时间戳变化；暂存与待推内容按对象读取。
- 固定本地 HEAD／origin/main SHA 并逐提交检查，结束再核对引用和索引；缺失对象标未完成，不当作删除。命令级 safe.directory 仅指向用户明确指定的规则仓库，不修改全局配置。
- 非白名单业务文件只检查路径，不读取正文；Git 配置、索引、引用和忽略规则作为必要元数据读取，允许文件的暂存／历史内容也做有限模式扫描。本地跟踪分支可能过时；不 fetch，不承诺远端最新。脚本自身和合成测试内容的模式命中仍须人工辨别。

维护该实现时，可按受影响范围运行 [Test-RulePreflight.ps1](../tests/Test-RulePreflight.ps1)：

```powershell
pwsh -NoProfile -File '<规则仓库>/tests/Test-RulePreflight.ps1' -TempRoot '<仓库外临时目录>'
```

该测试会在显式目录创建隔离夹具和合成 Git 提交，不是只读预检；不修改真实仓库或源文件、不联网、不自动删除夹具。不因使用通用规则而自动运行该测试。

## Claude Code 命令拦截钩子（可选）

用户明确选择启用该实现后，可用 PreToolUse 钩子在执行前审查 Bash/PowerShell 命令，作为部分硬闸的工具层安全网；规则本身仍是依据。未启用钩子不影响通用规则的适用，也不解除任何约束。

- 拦截：删除命令与 .NET 删除方法（A2）、`git clean`、不带 `--cached` 的 `git rm`、`cmd.exe` 与旧版 `powershell.exe`；传入 `-WorkspaceRoot` 时还拦截在该根目录执行 Git（含 `git -C <根>`、先 `cd` 到根），目录无法静态确定的 Git 命令也拦截。
- 无法审查即拦截：`Invoke-Expression`、别名定义、动态命令名或成员名、字符串编译为脚本块、`-EncodedCommand`、`eval`、git alias、`Start-Process` 启动解释器、无法解析的命令。嵌套的 `pwsh -c`、`bash -c`、`wsl`、`find -exec`、`xargs` 会递归检查；Python/Node 等内联代码只扫描常见删除 API。
- 不覆盖：脚本文件内部（`pwsh -File`、`source` 等）的删除、Edit/Write 工具的写入。它防的是误用，不是沙箱。
- 内部错误以退出码 2 失败关闭（PreToolUse 的阻断错误），不依赖 `onFailure`。
- 配置写在要启用的目录下的 `.claude/settings.local.json`，合并进已有 `hooks`，不覆盖其他配置；只有从该目录启动的 Claude Code 会话会加载。规则仓库本身需要用 Git，不传 `-WorkspaceRoot`。

```json
{
  "hooks": {
    "PreToolUse": [
      {
        "matcher": "Bash|PowerShell",
        "hooks": [
          {
            "type": "command",
            "command": "pwsh",
            "args": ["-NoProfile", "-File", "<规则仓库>/scripts/Guard-Command.ps1", "-WorkspaceRoot", "<工作区根目录>"],
            "timeout": 30,
            "onFailure": "block"
          }
        ]
      }
    ]
  }
}
```

- 回归测试：`pwsh -NoProfile -File <规则仓库>/tests/Test-GuardCommand.ps1`（只传入合成载荷，不执行其中命令）。
