# Bot 分工

触发：PZD 里拆票、认领、实施、交接、审计、提交或合并时读取。本文件只写 PZD 与通用规则不同或更严的部分，通用流程见[开发流程](开发流程.md)与 [Git与worktree](Git与worktree.md)。

## 1. 角色

| 角色 | git 身份（作者与提交者） | 职责 | 禁止 |
|---|---|---|---|
| **维护者**（用户本人） | 用户自己的 git 身份 | 拍板架构和一切偏离 [architecture.md](../../docs/architecture.md) 的做法；修改 `AGENTS.md`；决定是否合并到 `main` | — |
| **调度 Bot** | `PZD-调度Bot <dispatch-bot@pzd.local>` | 按架构 §18 拆票、分配、跟进度；把需要维护者拍板的问题一轮汇总 | 写实现代码；替维护者做架构决定 |
| **实现 Bot** | `PZD-实现Bot-<n> <impl-bot-<n>@pzd.local>`，`<n>` 从 1 起，每个实例一个编号 | 认领一张票，是这张票唯一的**主写入者**；代码和决策笔记放在同一个提交 | 同时认领两张票；碰别人认领的票；直接提交到 `main` |
| **审计 Bot** | `PZD-审计Bot <audit-bot@pzd.local>` | 通用规则工作原则 D2 的只读审查方：在实现 Bot 交来的 commit 上**独立重跑**验证，给出结论 | 修改实现代码；另建审计报告文件 |

- 一个会话只扮演一个角色，开场说明自己是哪个角色、哪个身份。
- **用户没指定角色时**（例如只说「继续」），先找票、只读汇报，再问一次本会话的角色，并给出推荐：有可认领的票就推荐「实现 Bot」，编号取 `git log --all --format=%an` 里还没出现过的最小 `PZD-实现Bot-<n>`。得到答复前不认领、不写入。
- 角色之间的权限不能借用：调度 Bot 不能「顺手」写代码，审计 Bot 发现问题只能退回，不能自己修。
- 需要偏离架构文档的事项，所有 Bot 只能等维护者回复，不许自行决定。

## 2. 票

- 票按通用规则[四阶段方法：位置与约定](四阶段技能.md#位置与约定)放在仓库内：`docs/work/<feature-id>/tickets/NN-<short-name>.md`，用到时再建。目录名和文件名一律**小写英文加连字符**，例如 `docs/work/tenant-core/tickets/01-tenant-resolution.md`。原因是中文路径在 Windows 下会被 GBK 读错，git 输出时也会被转义成 `"\350\247\204…"`，查找和比对都会出错。
- 每张票第一行起是通用规则[任务状态](开发流程.md#任务状态与中断)规定的任务头，共六个字段：`状态`、`主写入者`、`更新日期`、`下一步`、`交付状态`、`实施条件`（已具备，或写明还缺什么、来源是哪里）；正文写目标、范围、责任文件、关键接口与依赖、步骤、验收标准、证明它完成的验证命令和恢复方式；需要做取舍时另写 `proposed` 决策笔记并在票里链接（见[存储映射 §4](存储映射.md#4-不单独写开发计划与通用规则不同)）。
- **票面不全不认领**：正文缺少上面任何一项必填内容，`实施条件` 就必须写「待满足：<缺什么>」，不能写「已具备」。实现 Bot 遇到这种票只能退回调度 Bot 补全，不许自己猜着补完再开工。
- **认领**：在任务分支上把 `主写入者` 改成自己的身份名、`状态` 改成 `进行中`，提交并推送后才算认领成功。认领前先按 `AGENTS.md`「开始任务」的找票命令确认没有别的分支已经认领同一张票。别人认领过的票不能抢，要换人先问对方或调度 Bot。
- 一张票对应一个分支、一个 worktree、一个 PR。

### 找票

命令本身写在 `AGENTS.md`「开始任务」。这里写它为什么这样写，以及环境不满足时怎么办。

- **中文只放在模式文件里。** 「状态」和四个状态值写在 `docs/work/.find-tickets/open.txt`、`claimed.txt` 里，命令行只有 ASCII，git 按 UTF-8 直接读文件，不受 shell 编码影响。原因是 Windows PowerShell 5.1 会把没有 BOM 的 `.ps1` 按 GBK 读，里面的中文参数传给 git 后什么也匹配不到，退出码 1，看起来和「没有票」一样。改模式文件时保存为 UTF-8 无 BOM，一行一个正则；以后写给 5.1 跑的脚本也不要直接写中文。
- **没有 git**（`git --version` 失败）：只能看当前目录里的文件，看不到远端分支上的认领，也没法提交，所以只读汇报，不认领、不写入，并请维护者安装 Git for Windows（自带 Git Bash）。退路任选一种，结果都要标明「只看了本地，认领情况未核对」：
  - AI 工具自带的文件搜索，在 `docs/work/*/tickets/` 下找以 `状态：` 开头的行。
  - PowerShell 5.1 或 7（正则用 `\u` 转义，依次是「状态：」和四个状态值，同样只有 ASCII）：

    ```powershell
    Get-ChildItem docs/work -Recurse -Filter *.md | Where-Object { $_.Directory.Name -eq 'tickets' } |
      Select-String -Encoding UTF8 -Context 0,1 -Pattern '^\u72b6\u6001\uff1a(\u5f85\u5b9e\u65bd|\u8fdb\u884c\u4e2d|\u6682\u505c|\u963b\u585e)'
    ```

  - 有 `grep` 的 shell：`grep -rn -A1 -E -f docs/work/.find-tickets/open.txt --include='*.md' docs/work/`
- **`git fetch` 失败**（断网、没有凭据）：第四条看到的是上次 fetch 时的远端，可能漏掉新认领的票。照常列出结果，注明「远端未更新」，不认领，等 fetch 成功或维护者确认后再认领。分支从最新的 `main` 拉，命名为 `feat|fix|docs|chore/<票号>-<主题>`；同步用 `git merge main`，已推送的分支不许 rebase 或强推。

## 3. 一个工作树同一时间只允许一个写入方

通用规则[何时隔离](Git与worktree.md#何时隔离)只在有他人改动时才要求隔离。PZD 更严：

- 实现 Bot **一律**在 `.worktree/<票号>/` 下自己的 worktree 里工作，即使主工作树是干净的。
- 主工作树和 `main` 只接受合并，任何 Bot 都不在上面直接写代码。
- 开工前看到不属于自己的未提交改动就停下，报告维护者；不许删、不许覆盖、不许顺手提交。

## 4. 交接与审计结论

交接（调度 → 实现、实现 → 审计、审计 → 维护者）写进**票文件**，不另建交接或审计报告。通用规则 `.ai/交接/` 只用于票文件装不下的跨仓库接力。每次交接必须包含下面四项，缺一项接手方直接退回：

1. **目标**：这一步要证明或完成什么。
2. **提交**：完整的 commit hash 和所在分支。
3. **验证**：跑了什么命令、实际输出的关键行，原样粘贴，不许转述。
4. **遗留**：没做完、没验证到、需要谁拍板的事项；没有就写「无」。

审计结论也按这四项写，「目标」一项写成 `审计结论：通过 / 不通过`。审计 Bot 必须在实现 Bot 给出的那个 commit 上重跑；之后又有改动，就重新审计。同一张票只保留最新一次审计结论，旧的由 git 历史保留。

## 5. 完成与合并

- 「完成」的判定、证据分级、提交 / 推送 / 合入分开报告，都按通用规则[开发流程](开发流程.md#验证)和[状态判定](Git与worktree.md#状态判定)执行。
- 合并到 `main` 必须走 PR，并由维护者在 PR 或对话里明确同意；合并用 merge commit。合并后保留 worktree 和分支，按通用规则[文件整理](文件整理.md)再清理。

## 6. 提交

- 提交、推送、PR 的固定动作按通用规则[收尾](Git与worktree.md#收尾已授权的固定动作)执行。PZD 的差异只有下面三条。
- 提交信息用简体中文，格式为 `feat|fix|test|docs|chore(scope): …`。
- 笔记与它记录的改动放在**同一个提交**里。
- **署名**：每个 Bot 用本文件「1. 角色」里自己的 git 身份作为作者和提交者，例如：

  ```bash
  git -c user.name="PZD-实现Bot-1" -c user.email="impl-bot-1@pzd.local" commit
  ```

  不加任何 `Co-Authored-By` 行，也不用工具默认的 AI 署名；本条优先于工具自带的署名设置。维护者自己的提交用维护者自己的身份。
