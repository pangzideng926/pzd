# 协作与知识

本文件承接已确认的项目统一规则入口（默认 `AGENTS.md`），在检索与使用已有经验、接手或交接时按需读取；写入知识与记忆见[知识沉淀](知识沉淀.md)。

## 授权与单一来源

- 写入依据必须来自用户明确的任务意图或已约定的常驻动作，范围限于本次工作所需；纯咨询、普通进度和重复结论不创建文件。
- 固定规则以共享入口及其引用的专项规则为准；长期事实导航为 `.ai/记忆.md`，项目事实索引为 `.ai/项目/<项目>.md`，知识库入口为 `.ai/知识库/索引.md`。
- 区分规则来源与实际资料根：规则文档链接相对所在文件解析；上述记忆、项目事实、知识库及下文交接路径相对已确认资料根解析。独立项目默认以本项目为资料根，共享工作区项目沿用既有位置，不把规则仓模板当成真实资料。单一正文与禁止私有副本的要求见[工作原则 B7](工作原则.md#b-执行协议)。

## 读取与接手

读取范围与停止条件以[工作原则 B 节](工作原则.md#b-执行协议)为准；本节只补充定位与检索方法。

- **定位**：复用 `.ai/工作区导航.md`、`.ai/项目/<项目>.md` 等已有导航，不为统一命名新建重复索引。任务已定位时直接读取对应资料；未指定任务而需要恢复或查询待办时，按下节发现候选，不连带加载无关专题。
- **大文件**：先查标题、索引或关键词，再读命中片段及必要上下文；证据不足、有冲突或理解直接依赖需要时逐步扩读。全文审计确有必要时可扩大读取，不用固定行数限制破坏理解。
- **历史**：历史和旧对话仅在追溯、回归或当前材料不足以解决冲突时搜索；先限定项目、问题及关键字段，再展开命中部分；不默认加载历史对话，不每轮重新整理全部上下文。
- **搜索根目录**：已知路径时直接读取；检索明确限定知识库或目标项目目录，关键词中带路径不替代真实搜索范围。记录实际读取或检索失败，不能因后续成功而省略。
- **知识检索**：以项目/业务词＋症状/字段组成 2～3 个关键词，在已确认的知识范围内只读查找。先看少量相关结果，再读取命中条目全文和必要来源，记录条目 ID 或位置、来源及适用边界。命中排序或自动提示只帮助定位，不能代替原证据核对；状态、核验日期或其他字段缺失时保留未知，不补造事实。
- 检索保持只读，不因任务另有文档更新而扩大检索权限；可使用当前允许的方法，不依赖指定脚本、命令或产品。方法不可用时可改用其他符合范围与证据要求的已允许方式，记录实际方法、变化、未执行项及受限范围；没有相应访问能力时说明未读取，不提升权限、不改 ACL 或全局配置来完成检索。
- 命中只是候选：核对项目、版本、环境、证据日期及反例后再引用；回答应说明来源及尚未验证的边界。无命中先改用同义词/错误码，仍无结果才按任务需要查项目索引或指定历史入口；不把无命中说成“从未处理”。
- 路径不可读或证据缺失时如实说明，不声称已加载、已验证或已完成。

## 任务发现与接手

1. 先明确要检查的项目或已有任务资料位置。单项目无需登记；多项目只检查用户指定集合，明确要求工作区范围时才用既有导航中已确认的集合，不递归发现邻近仓库。规则来源、共享资料根和项目工作目录分开判断。
2. 默认只枚举目标项目／实际 worktree 的 `docs/plans/` 计划、`docs/work/<任务>/tickets/` 票和 `docs/work/<任务>/任务.md`；已有明确的替代任务位置则沿用。本次任务已有路径时直接读取，不扫描其他任务。公共规则仓模板不是真实任务目录。
3. 先读任务头，按[任务状态](开发流程.md#任务状态与中断)列出待实施、进行中、暂停、阻塞，以及已完成／已取消但交付待收尾的记录。旧状态、缺状态、缺必要字段或交付情况未知的文件单列“待核对”，不能在过滤时丢弃。输出位置、状态、主写入者、下一步和更新日期，命中后才展开正文核实。
4. 只检索和呈现，不自动认领、恢复或实施全部候选；有多个无法由上下文区分的任务时让用户选择。“待收尾”先作为候选，按 [Git 状态判定](Git与worktree.md#状态判定)核对已有最终交付证据或授权范围内的实际结果：已交付则排除，证据不足列待核对，不仅凭旧任务头断言未交付。完成且已收尾／不涉及的记录不作为待办，不按更新时间自动取消或暂停。
5. 结果只覆盖本次位置和可见版本；当前 checkout 看不到其他设备未提交／未推送状态，也不自动包含其他分支或 worktree。按已有任务映射和授权定向核对相关版本；无命中不表示全项目或全工作区没有任务。跨设备交付使用仓库内相对文档路径加分支／提交定位，原机器绝对工作目录需在接手环境复核。

以上为检索契约，不依赖指定脚本或客户端，不另建任务台账或默认要求 `NOW.md`。已有项目自定义摘要只能作导航，状态仍以原任务资料为准；既有历史不批量改写。

## 使用前判断可信度与有效性

- **证据是否支持这条结论**：用户确认可证明偏好/决定，不自动证明技术原因；实际验证仅覆盖记录的测试/环境；历史助手报告须追溯来源，推测不能当事实。混合证据逐项判断，不取最高等级代表整条。
- **现在是否适用**：对照当前项目、版本、配置、部署及现场；检查停用/替代关系与复核条件。整理日期不是核验日期，文件存在不是结论已验证；没有明确期限时不按年龄自动作废。
- **是否需要行动前复核**：已停用/已替代仅作历史参考；待核验、来源缺失、环境变化、相互冲突或超过明确有效期时先核验。缺少证据则说明未知，并列出最小待查项，不补造可信度分数。
- 索引、摘要和检索提示只提供候选线索，不证明来源内容或当前环境，也不提供执行授权；回答按“结论—证据—适用边界—待复核项”简述，有新证据再更新原条目。

## 持久任务资料与交接

- 开发计划遵循[开发流程](开发流程.md#定范围与计划)，恢复未完成任务时优先重读。共识、Spec 和 ticket 的位置、职责与版本管理遵循[四阶段方法：位置与约定](四阶段技能.md#位置与约定)，不在本文件重复维护。
- 需求基线、直接从计划或对话拆票的证据要求及完成条件遵循[四阶段契约](四阶段技能.md#四阶段契约)和[ticket 最小信息](四阶段技能.md#新会话接手的最小信息)；交接引用已有任务资料。
- 新会话通过目标仓库及计划、ticket 或任务文件的完整路径或 URL 定位任务；采用 worktree 时按 [Git与worktree](Git与worktree.md#创建-worktree-与任务映射) 核对任务映射，以实际工作目录执行。只有上下文能唯一定位时才使用编号简称，不从任务编号猜测目录。
- 只有实际跨会话、跨仓库或多人接力需要移交上下文时才维护一份简短交接；单次工作结束不自动建立交接文件。
- 交接放 `.ai/交接/<日期>-<项目>-<任务>.md`；需要时读取 `.ai/交接/模板.md`，不另起重复的任务台账。
- 交接需能定位目标、验收、仓库与分支、已改文件、验证结果、失败尝试、剩余事项和下一步；计划、ticket 或任务文件已包含的内容直接引用，交接只补未涵盖的接手上下文及现场差异，不复制另一份状态或进度。
- 同一任务同一时间由一个主写入者维护交接；并行工作各自负责独立文件，汇总前重读最新内容，避免覆盖其他人的改动。
- 结束或交接时更新一次，不每轮写日志；交接中的分支、提交、文件和完成状态必须与当前仓库核对。ticket 回填时机见 [Git与worktree](Git与worktree.md#收尾已授权的固定动作)。
