# 个人通用规则维护与预检

本文件维护三层职责与同步边界的唯一正文。README、仓库入口和本地入口仅引用。默认操作为离线只读预检，不拷贝文件、不提交、不推送。

## 三层职责

| 层级 | 权威位置与职责 | 修改方向 |
|---|---|---|
| 通用规则 | 本规则仓库的本地检出目录；远端只负责版本保存与分发 | 通用改进直接在本仓形成差异；明确授权发布时才提交推送 |
| 本地工作区 | 环境路径、已安装工具、权限和个人工作区适配；通过入口引用通用正文 | 本地修改只影响环境差异，不反向整份覆盖通用规则 |
| 项目 | 项目契约、验证命令、真实事故、任务状态和现场证据 | 保留在项目边界内；提炼可复用经验时人工生成脱敏候选 |

“权威正文”是维护职责，不扩大权限，也不绕过现行项目约束。发生冲突先识别适用范围并核实，不静默取更宽松规则。

## 过渡与去重

- 逐份记录本地迁移状态：已核对并迁移的规则以本仓为正文，本地旧路径仅保留引用；未迁移的兼容副本继续保持原有执行效力。实际迁移清单留在本地，不能仅凭本表认为所有工具都已切换。
- 后续按任务逐份核对有效约束、环境差异与直接引用，完成备份和可读性核验后才把本地正文换成引用。路径不可读时报告阻塞，不声称已加载，不偷偷复制回双份正文。
- 两边不同不等于本地更新；未保存可靠的上次对应版本时人工逐段判断。源文件缺失不授权删除目标。备份恢复先比较当前差异，保留其他会话更新。
- 本仓独立维护通用正文、入口适配、空白模板，以及已明确保留的可选脚本与测试；具体实现按需参考[工具接入](../工具接入.md)，不作为通用规则执行前提，不从实际工作区覆盖这些文件。规则正文和项目材料混合时只提炼通用原则，不自动复制或自动脱敏。

## 直接调用

> 按个人通用规则入口执行只读预检，只报告差异、需人工核查项和未检查范围，不拷贝文件、不提交、不推送。

核对已明确的本地资料范围与规则仓库，分别记录相同、差异、缺失、需要人工核查及未检查部分。核对引用、适用范围、原有改动与发布候选；只读核查不授权拷贝、修改或发布。

可采用当前允许的人工核对或检查实现，方法、对象与结果应可复核。只有明确选择脚本实现时才按[可选工具接入](../工具接入.md)读取参数、输出和限制；实现返回成功不等于差异已处理或可发布。

## 预检范围与限制

- 选择现有脚本实现时，其输出、检查范围与技术限制仅在[通用规则预检可选说明](../工具接入.md#通用规则预检可选)维护；不作为其他核验方法的必备接口，也不代替本文件的人工审核与发布要求。
- 禁止上传业务代码、客户与项目资料、真实登记/事故/记忆/日志/报告/交接、截图附件、聊天、备份归档、环境配置、凭据与业务 Git 历史。空白模板不允许混入真实案例；.gitignore 不替代审核。

## 修改与发布（单独明确授权后）

1. 把可公开经验提炼为本仓候选变更，保留有效约束和本地适配；人工确认范围、脱敏、引用和证据，不自动合并两边正文。
2. 改前备份并核对源/目标指纹；备份和预检输出保留在规则仓库外的本地目录。发生并行变化重读，不覆盖、不 stash 他人修改。
3. 明确要求发布后才核对 origin 的 fetch/push URL 指向 `https://github.com/pangzideng926/pzd_Workflow.git`，核验 main 与远端状态；冲突、非快进或权限问题停下依赖步骤，不改配置绕过。
4. 逐文件及逐提交检查全部待发布差异，限定 git add 路径；执行差异检查后按授权提交和正常推送，禁止强推。最终核对完整远端 SHA。无变化不做空提交。

通用规则变更核对本次引用、锚点、职责和关键约束；改动具体实现时才执行其相关回归。原始证据与计划留在已确认资料根，不纳入公共规则仓；可选实现的参数与回归入口见[工具接入](../工具接入.md)。
