# 子仓库接入

本文件适用于独立项目和工作区子仓库，仅在创建、首次接入或调整规则入口时读取。

## 触发与范围

- 创建或首次接入项目时，在首次交付前补齐项目统一规则入口；已有明确入口时沿用，否则使用项目根目录的 `AGENTS.md`，不另建接入任务。
- 接入动作属于已授权建仓或接入工作的常驻步骤；纯咨询不创建文件，不批量补改未涉及的仓库。
- 先定位当前目标仓库并读取已有入口，保留项目专属约束、用户和其他 AI 的改动，不覆盖整份文件。

## 模板与引用

- 先明确规则入口与资料根。共享工作区项目使用已确认共享入口及既有资料根；独立项目引用已配置的规则来源，资料默认位于本项目，无须存在父工作区入口或先登记。复盘范围和资料位置见[复盘通用约定](每日复盘.md#复盘通用约定)。
- 需要统一入口模板时，从规则来源目录的 `.ai/模板/子仓库/AGENTS.md` 读取，不在资料根猜测模板位置。客户端桥接仅在实际需要时按现有适配补充。
- 缺失统一入口时套用模板，以 UTF8 编码写入；已有入口仅补充缺失引用，不为未使用的客户端额外创建文件。
- 项目统一规则入口（默认 `AGENTS.md`）记录已确认的外部规则入口，要求尚未加载时先读取其适用专项规则；已加载且未变则跳过。不把项目自身入口再次作为外部规则入口，避免循环引用。
- 同一项目入口记录资料根，记忆和知识入口为该资料根的 `.ai/记忆.md` 和 `.ai/知识库/索引.md`，按接手需要和问题展开；独立项目没有这些资料时不强制创建空文件。
- 需要客户端桥接时，只指向已确认的统一入口，保留原有项目专属内容；不维护另一份共享规则。
- 其他工具入口只引用统一规范；共享路径、读取指令及项目专属约束以已确认的项目统一规则入口为主，不依赖工具跨 Git 边界自动继承父目录规则。
- 入口只引用规则、记忆和知识库（工作原则 B7）。规则文档链接相对其所在文件解析；实际资料路径相对已确认资料根解析，不把通用规则仓库中的模板当成真实知识库。
- 路径不存在或权限受限时如实说明，保留现有内容，不声称已加载。

## 按需开发流程配置

- 四阶段方法“对齐需求 → 规格 → 拆任务 → 实施验证”的项目适配只放已确认的项目统一规则入口，其他入口引用它；具体执行遵循已配置规则来源的[开发流程](开发流程.md)。
- 四阶段按任务需要选择入口，不把访谈、共识文档、Spec 或拆票设为所有任务的固定关卡。
- 共识、Spec 和 ticket 的资料契约见[四阶段方法：位置与约定](四阶段技能.md#位置与约定)，开发计划见[开发流程](开发流程.md#定范围与计划)；接入不额外生成或迁移阶段资料。项目术语与 ADR 见[知识沉淀](知识沉淀.md)，任务文档的单一正文要求见工作原则 B7。
- 接入不重建整库索引（常驻机制与扫描限制见工作原则 B6、B7）。

## 最小验证与收尾

- 只核对当前仓库实际采用的入口、其引用的共享目标可读性，以及已有局部规则是否冲突；不批量复查其他仓库，不为入口文档运行业务测试。
- 共享工作区仅在需要登记时更新既有登记中的当前仓库记录；独立项目不要求建立工作区登记，不重复抄写规则。
- 在实际项目目录遵循[Git与worktree](Git与worktree.md)的收尾约定；仅处理本次入口改动，保护他人的未提交及已暂存内容。用户限制提交或推送时遵循限制。
- 有新增可复用结论时，结束后按[知识沉淀](知识沉淀.md)增量沉淀一次，无新增则跳过。
