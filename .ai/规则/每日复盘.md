# 每日代码与协作复盘

适用于独立项目与多项目工作区。每日检查代码增量和 AI 协作事件；[每周蒸馏](每周蒸馏.md)复用这些证据，归纳共性、纠正旧结论并优化规则。本文件维护两者共用的范围、自动修复和事故去重约定。

开发、Git、知识沉淀等专项依赖沿接入入口已明确的现行映射，引用本日周规则不表示迁移其他专项。未另配时，代码复盘的证据字段与复用遵循[开发流程：验证证据分级](开发流程.md#验证证据分级)（使用 L2），Git 判定遵循 [Git与worktree](Git与worktree.md)；下文 L2 在已有接入中对应其现行完整复盘／合并证据要求。纯协作或文档事项记录来源、文件版本或指纹、核验方法、结果与未覆盖项；没有被测代码时不编造 SHA 或业务测试。

## 复盘通用约定

- **触发与授权**：人工触发，或在已明确的交付收尾范围内执行；不自动调度（工作原则 B7）。允许读取本次范围内的必要证据、写复盘记录与错题本，并按[自动修复与入库](#自动修复与入库)处理。其他修改沿已有授权；机制本身不授权提交、推送、合并、部署、生产写入或扩大权限。
- **范围**：用户指定范围优先；上下文唯一明确为当前项目时按单项目执行。只有明确要求工作区复盘才读取资料根 `.ai/子仓库接入检查.md` 的实际登记并使用全部纳入项目；本仓[项目登记模板](../子仓库接入检查.md#每日复盘项目登记)仅供格式参考，不能当成真实项目集合。范围仍不明确时只询问缺失项，不递归发现仓库；登记是导航，不扩大授权。
- **单项目**：记录实际项目路径、目标引用确认依据与核验方法或项目既有验证入口即可，无需先登记；缺失项标未知。普通开发只读取当前项目的相关教训、未解决项与必要证据。
- **多项目**：按本次选定集合逐仓核验，保留各仓目标、快照、限制、问题和阻塞；先完成各仓审查覆盖，再处理一般缺陷。主线确认失败测试仍立即定位，有条件时与其他仓只读审查并行；一仓受阻不阻断其他独立检查。
- **主线与 Git**：目标引用以现有项目约定、已确认登记或用户指定为依据，不从当前 checkout、origin/HEAD 或 main/master 名称推断。未确认时仅作注明边界的候选快照；无法确定候选引用则标提交覆盖未验证，协作事件可独立取证。所有 Git 取证明确对应实际仓库，禁止在非 Git 多项目容器操作 Git；不擅自同步远端、切分支或改工作树。
- **规则与资料位置**：执行前区分规则来源目录与资料根目录。已接入共享工作区的项目沿用既有共享资料根；独立项目默认以自身为资料根，将报告与知识存入自身 `.ai/`。多个独立项目各留本项目证据，汇总写在本次已明确的资料根并链接它们；汇总位置不明确时先交付对话汇总，不新建共享目录。通用规则仓库的模板链接只提供格式，不能作为真实报告或错题的写入目标；同一事实保持一份正文。
- **每日与每周**：每日处理新增提交和协作事件，每周优先复用日报、相关任务资料和错题本，仅按缺口追溯原证据或重验变化部分。当天发现不等待周末处理；周报完成不解除既有阻塞。无新增可复用结论时不强行生成规则或错题。

## 自动修复与入库

- 复盘已触发后，范围内有证据、可恢复且有明确验证办法的问题，按“确认问题 → 修复 → 验证 → 去重入库”执行，无需逐条确认；按工作原则保留恢复依据，写前重读并保留并行改动。
- 新增自动修复权限限于规则重复、依据明确的规则纠错、文档与模板遗漏、坏链接、路径引用错误及不影响运行的说明性问题。按实际影响判断，不能仅凭文件扩展名或“静态问题”标签判断安全。
- 规则冲突仅在现行权威正文能确定答案时纠正；权威不明或需要选择政策时保留具体待决点。不得据此改变业务语义、产品运行行为、权限、对外契约或削弱门禁；测试、工具脚本、依赖和运行配置的行为修改不在本次新增权限内，已有任务授权继续有效。
- 修改只限本次明确的项目、规则及资料范围；发现共性不自动扫描或修改全部接入项目。其他问题记录根因、影响及最小修复方案，按既有授权继续；缺少所需授权时只询问该项。
- 修复后核验实际差异、引用目标及相应约束。验证失败或无法完成时保留“未解决”、失败证据和原阻塞，不称已闭合；需要恢复时先核对最新差异，只恢复本次改动，不覆盖他人内容。
- 问题已确认与修复已验证分开记录。有证据的根因可以入库并注明待修复或已修改待验证；修复建议标“待验证”，未经验证不得写成成功经验。只有疑点则留在复盘待核实项。
- 入库前按根因和适用范围去重，补充原条目的证据、边界或纠正记录；无实质新增不写。提炼为通用规则须有可追溯证据、明确适用边界和可执行的检查办法，优先修正已有规则，不按 Seen 数量机械升级。

## 边界

范围与修复权限统一见[复盘通用约定](#复盘通用约定)和[自动修复与入库](#自动修复与入库)。

每日记录位于资料根的 `.ai/验证/每日复盘/<日期>/复盘.md`。独立单项目直接记录本项目；共享工作区按既有位置保留汇总与分仓证据，有详细审查或阻塞时才建 `<项目键>/复盘.md`。同日新快照用 `快照-<HHmmss>/` 分隔，不覆盖原快照；已被引用的旧证据原位保留。

## 每日复盘执行任务

用户要求每日复盘时按以下步骤；旧称“每日提交复盘”仍可使用。用户明确只查提交或协作时，遵循指定范围。

1. **确定范围**：按[复盘通用约定](#复盘通用约定)确认项目集合、规则来源和资料根。默认 Asia/Shanghai 当天 00:00 至执行时刻，标“截至本次快照”；记录排除项、目标引用依据、核验方法及未解决事项。
2. **冻结快照并生成覆盖清单**：对范围内需检查提交且引用已明确的 Git 仓库，以可用的只读方式核对版本历史、引用和差异，固定本次截止状态，形成一份可追溯的提交覆盖清单。记录方法、原始依据及缺口，不拼接互相矛盾的结果冒充完整覆盖。没有代码提交不免除协作事件复盘，非 Git 项目标注提交检查不适用；历史不可读时标提交覆盖未验证，继续可独立取证的协作事项。

   - 清单至少记录目标引用与依据、截止 SHA、上次已覆盖基线、工作树改动状态、第一父链进入事件、合并带入提交（含旧日期提交）、按完整 SHA 去重的待审提交、内层合并、已识别的等价补丁及限制。取证不得更改仓库或执行未经审查的扩展；无法安全确认的状态标未知，不为取证修改配置或扩大权限。
   - 有有效基线时核对基线至截止的提交区间。是否当天进入目标须有引用变更或可信合入记录支持；提交日期不代表进入时间，只有提交日期时标“待核实”。补查区间与当天进入事件分开记录。
   - 无基线、基线对象不存在或基线不是祖先时，按时间窗口列候选并写入限制；不能把零候选当作远端零合入。
   - 同日多次执行时，以上次快照截止 SHA 为基线得到的是本轮增量；日报保留当天累计覆盖与本轮增量，不把增量冒充全天覆盖。
   - 本地快照不代表远端完整复盘。后者须在已有授权内取得最新远端状态、可信合入及对应验证证据；做不到则保留完整性缺口，不因复盘触发自动同步。
   - 与上次已覆盖 SHA 相同且无未闭合疑点的仓库，只记录截止 SHA 与限制；已覆盖提交引用原证据，但变化的集成上下文仍须检查。未解决问题不因主线无新增而解除。
3. **逐项审查**：对覆盖清单中的每个待审提交阅读实际差异；对每个合并（含内层合并）检查相对第一父的集成差异、冲突解决和额外修改，空合并也记录集成检查。另检查范围内新增的需求理解、执行遗漏、重复返工、验证声明和规则遵循事件；依据明确任务约定、具体交互、实际执行记录或产物，不以情绪、轮数或沉默判断对错。代码与协作覆盖分别记录；摘要和历史助手报告不能替代原证据。重点见[判断与处理](#判断与处理)。
4. **处理问题**：按[自动修复与入库](#自动修复与入库)和[判断与处理](#判断与处理)执行。当天发现及时处理，无法完成时明确未解决原因和恢复条件，不等待每周蒸馏。
5. **保存验证证据**：代码复盘按 L2，协作与文档按本文证据要求记录；静态核对、场景推演、实际执行分别标明，本轮新增与复用证据分列。文档整理不跑无关业务测试。
6. **更新错题本与日报**：按[错题本维护](#错题本维护)和[记录模板](#记录模板)写入；同日新快照保留旧证据。零提交但有协作案例或未解决问题时仍记录；没有新增、案例或未决项的仓库只留覆盖说明，不建空分仓报告。
7. **核验与交付**：核对覆盖与计数、证据与候选的对应关系、链接及引用内容、同类清单、修复状态和未决项；写入前核对并行变化，按规则备份，不整文件回拷覆盖其他会话。报告实际改动、覆盖范围、确认问题、修复、验证与阻塞；不声称未经证明的可合并。需要新增授权时列明范围，继续独立工作。

日常调用：`按每日复盘规则，复盘当前项目今天的代码增量和 AI 协作问题，符合范围的静态问题直接修复、验证并去重入库。` 多项目明确列出项目，或明确要求工作区全部登记项目；可追加日期和复盘模式。

## 判断与处理

四类结论，按事项分别使用：

| 结论 | 含义 |
|---|---|
| 已确认 | 有可追溯证据证明具体问题 |
| 待核实 | 有疑点但缺决定性证据；列出缺项与最小核实动作 |
| 未发现 | 在明确的已检查范围内未找到问题 |
| 未验证 | 检查或业务／现场场景未运行 |

- **重点检查**：返工（遗漏根因、影响范围或同类位置，导致补修／回滚）；不该合入（违反明确需求或约束，存在阻塞缺陷或必要检查失败）；验证粗糙（漏关键场景、断言不足、测试对象与最终提交不一致）。缺日志只证明证据不足；同一文件多次修改不直接证明返工。
- **发现记录**：项目、事故标识、文件或事件位置、触发条件、根因、后果、需求依据、证据位置，并注明证据来自本轮实测、代码／契约直接对照还是历史记录。无提交事件使用任务或会话标识加具体事件定位；缺原始证据时留待核实。编译、静态检查、部署成功分别记录，不能替代业务或现场验收。
- **同类闭合**：确认 bug 后，按根因定向查相同代码模式、调用链与业务门禁，记录每个命中位置及处理结果（修复／已正确／不适用／阻塞），覆盖代表性正反例；清单闭合才算完成。跨日独立复发时检查前次遗漏原因，不借机做无关重构。跨项目只在有适用契约或同根因证据时扩展，不自动跨仓扫描或扩大写入。高风险逻辑按开发流程先失败测试再修复。
- **主线失败测试**：视为当前待修 bug，立即定位产品、测试资产或环境根因；“历史遗留”不能搁置。不得跳过测试、删有效断言或降门禁；测试退役须有已确认的业务契约依据。
- **合并阻塞**：确认失败未解决前，该“仓库＋目标分支”阻止后续普通合并；修复候选通过相关验证后可按已有授权进入修复集成，目标上的必要验证通过才解除阻塞。修复、验证与集成按[状态判定](Git与worktree.md#状态判定)分开记录，任务分支通过不能提前解除目标阻塞。阻塞相互独立，只有真实跨仓契约或共同发布依赖才扩大，并给出证据。合并前读该仓最新未解决项，修复回链原事故并记录解除证据；不能凭另一仓通过、历史日报或复用的通过记录解除。
- 环境、权限或外部阻塞：记录责任动作、恢复条件、受阻检查与状态“未解决”，继续独立工作。本机制由 AI 入口执行，不宣称已安装服务器端强制门禁。

## 复发诊断

先区分同一事故的补修与新的独立事故。只有后者增加 Seen；确认独立复发后，对照事发时实际生效的规则版本、加载记录、动作和验证结果，诊断前次措施为何没有防住。以下为可并列的原因标签，不替代业务根因：

| 原因 | 所需证据 | 对应改进 |
|---|---|---|
| 规则未加载 | 必要正文未进入事发前上下文的加载记录，或入口明确不可达 | 修正入口、路由或可读性，再验首次决策前是否加载 |
| 表述不清 | 现行文字存在具体歧义，且与错误决策对应 | 补触发条件、适用边界或一个正反例 |
| 规则冲突 | 同时适用的正文条款不兼容 | 有权威依据才纠错，否则保留具体待决点 |
| 已读未执行 | 正文已加载，要求明确，但实际动作违反要求 | 在对应动作前加必要检查点并做行为验收 |
| 验证遗漏 | 应验证的场景或对象有依据，实际检查未覆盖 | 补相关验证入口、失败反例或交付核对 |
| 原因未明 | 现有证据不能区分以上原因 | 写缺失证据及最小核实动作，保持待核实 |

没有加载日志不等于规则未加载；有加载日志不等于已理解或执行。一个事故可标多个有证据的原因，但仍计一次；只有复发次数没有时序证据时，不加“更严格遵守”等空泛规则，不推断模型意图。

## 记录模板

单项目、工作区汇总与分仓记录复用同一模板。先写需要行动的结论，再写覆盖与证据；仅填写适用字段，已有明细使用链接，不复制正文：

```markdown
# YYYY-MM-DD 每日复盘（截至本次快照）
## 行动摘要
| 项目／事故 | 新增问题与影响 | 修复状态／验证结果 | 阻塞及下一步（责任动作、恢复条件） |
|---|---|---|---|
- 无新增时：写明无新增；原未解决项仍列出。未检查不写成无问题。

## 范围与证据索引
- 本地快照／远端完整复盘／协作事项；单项目／工作区汇总／项目键：
- 规则来源／资料根：
- 时区／开始／截止：
- 仓库范围、排除项及原因：
- 各仓快照与覆盖清单位置、目标引用／截止 SHA／上次基线／工作树状态／限制：
| 仓库 | 进入事件 | 完整 SHA（含旧日期带入） | 实际差异／位置 | 需求及验证证据 | 结论／处理 |
|---|---|---|---|---|---|
- 协作案例：事故标识、任务／会话及事件定位、约定与原始证据、根因状态、处理结果；独立复发另列原因标签及证据；没有时写无，无法覆盖写缺项。
- 覆盖：提交进入事件、已读／未读提交、协作案例分别计数；等价补丁对应；已运行快照的零提交仓库也列截止 SHA。
- 已确认／待核实／未发现／未验证：
- 同类清单、修复状态、错题本回链、普通合并阻塞与恢复条件：
- 本轮验证：静态核对／场景推演／实际执行注明类型，新增与复用分列；代码按 L2，协作或文档注明来源、文件版本／指纹、核验方法、结果与未覆盖项。
```

独立单项目只填本项目记录；工作区汇总只填本次范围的覆盖、各仓摘要、阻塞及分仓链接。分仓记录保存提交、协作案例、证据和状态，并引用唯一错题正文与修复计划。验证入口未知或检查未跑必须明记，不能自动补“通过”。

## 错题本维护

- 以根因组织教训；项目、模块、日期作为范围和检索信息，不按日／周各建一套错题本。保留既有编号，用“关键词”标注需求理解、设计实现、验证交付、规则协作、工具环境等类型和相关项目；旧条目在实质更新时补充，不重编编号或批量重写历史。
- 只收录有证据的教训。同根因且适用契约一致时合并；跨项目或相似词不证明同根因。独立复发才增加 Seen，同一事故的补修、日周复用或跨仓引用只计一次；问题族、任务数、补修轮数不等于事故数。
- 代码事故使用“仓库＋事故 SHA／issue”；无提交事故使用“项目＋任务／会话标识＋具体事件定位”。同一事故涉及多个项目时确定统一事故标识，各仓记录回链它，项目只作为关联范围，不重复计次；缺事件或根因证据则待核实。后续修复回链原事故。
- 快照内及跨快照的等价补丁，按实际差异、相关上下文与原事故证据核对对应关系；提交 SHA 改变不直接构成独立复发，差异等价也不免除集成上下文检查。缺少对应证据时保留待核实，不重复计次或直接合条。
- 已确认根因、修复状态和验证范围分开记录，规则见[自动修复与入库](#自动修复与入库)。格式见 [AI错题本空白模板](../知识库/AI错题本.md)；真实正文写入已明确资料根的知识库，已有主题只引用，不复制到规则仓库或其他知识条目。
- 新增或实质更新时可逐行维护 `- 事故 ID：<稳定标识>`；只有该条目的历史独立事故清单已核实完整，才写 `- 事故 ID 完整：是`。未完整时标“否”或省略；不得为凑 Seen 补造 ID。它是计次台账，事故说明和原证据仍须保留。
- 开发前如何检索错题本见[开发流程](开发流程.md#定范围与计划)。

## 错题本只读检查

更新了错题正文或需要核查结构时，明确实际资料根和选定文件，以可用的只读方式核对编号、证据引用、链接及 Seen 台账；不因此扫描全部知识库，不依赖某个脚本或工具是否可用。

- 分开记录检查是否完成、确认的问题与未检查项。无法读取、无法识别的格式或无法判断的引用标未知，不把空结果当无问题，也不把检查完成当全部通过。
- 链接可达、锚点存在和引用内容支持结论分别核对；未读取原证据不能声称证据已验证。范围外引用不自动追读，路径访问遵循现有权限与文件边界，缺项明确记录。
- 只有历史独立事故清单已核实完整（标为“事故 ID 完整：是”）时，才比较唯一 ID 数量与 Seen；账面一致不证明事故独立性或证据真实性。
- 旧事故、来源或验证说明只提供待核验线索；缺新版字段不等于缺证据，不据此批量重写。记录选定文件的版本或指纹，写入前仍须核对并行变化，不能假定多文件读取具有原子性。

确认发现后的修改仍遵循[自动修复与入库](#自动修复与入库)；只读检查本身不新增修复授权。

## 规则行为验收

范围选择、授权、修复状态、计次或规则入口发生实质变化时，明确受影响场景的触发条件、输入、允许与禁止的动作、可观察结果，再按风险选择核验方式。按改动覆盖相关的单／多项目、规则根与资料根、零提交协作、自动修复成功或失败、同事故复用与独立复发、未解决阻塞等场景；不要求每次重验全部场景。纯措辞和链接修改做对应静态核对即可。

静态核对证明文字、引用或结构符合约束；场景推演说明预期决策及尚未观察的结果；实际执行须有对应输入、真实动作与产物支持。三者分别记录，前两者不能冒充实际行为通过。注明规则版本或指纹、核验方法、结果、未覆盖项及本轮新增／复用证据，不用历史报告或最终自述代替真实执行记录。

核验不绑定特定工具、CLI 或模型，也不默认启动额外模型。实际执行条件不足时标未验证及恢复条件，不扩大权限；已通过且输入、规则与适用环境未变的证据可复用，只有新变化、失败或未决风险才补验受影响部分。
