# 01 号票 `dotnet test` 本体补跑：交接与定位

- 执行人：PZD-测试Bot（李总）
- 时间：2026-10-29 17:50–17:56（Asia/Shanghai）
- 目的：老登在 01 审计结论里点名「`dotnet test` 本体等普通终端补跑一次」

## 一、结论：我这边做不了，需维护者本机终端或 CI 跑一次

`dotnet test` 本体在这套 Bot 执行环境里**跑不起来**，不是代码问题、也不是 `global.json` 配置问题。三家（旺总、老登、我）在各自环境里撞的是同一条异常，退出码一致，说明这是**执行环境的共性限制**，不是某台机器的偶发。

请维护者在自己的终端（普通 PowerShell / Git Bash，不经 Bot 执行环境）跑：

```bash
cd E:/pzd/.worktree/01        # 或任意 01 分支的干净 checkout
git log --oneline -1          # 确认被测 SHA
dotnet test Pzd.slnx
```

**期望输出**（通过形态）：

```
已成功生成。
    0 个警告
    0 个错误
测试运行摘要: 成功!
  总计: 1
  失败: 0
  成功: 1
  已跳过: 0
```

**通过判据**：`总计 >= 1`、`失败: 0`、`成功: 1`、退出码 `0`。
**必须拒绝的形态**：`总计: 0`（不论是退出码 0 还是非 0），或出现 `NamedPipeClientStream` 异常。看到这两种就按 01 票「假绿防线」四项如实记「未运行」。

CI 落地后（04 号票）应由 runner 兜这一条，本机补跑只作一次性闭环。

## 二、定位过程：不是命名管道不可用，是 MTP 握手被拒

我把范围一步步缩小了，避免团队下次又从头猜：

1. **MTP 报错原文**（两家一致，`dotnet test Pzd.slnx` 与 `dotnet test tests/Pzd.ArchitectureTests` 都一样）：

   ```
   Pzd.ArchitectureTests.dll (net10.0) 运行了零个测试
   退出代码: -532462766
     错误输出: Unhandled exception. System.UnauthorizedAccessException: Access to the path is denied.
        at System.IO.Pipes.NamedPipeClientStream.TryConnect(Int32 timeout)
        at Microsoft.Testing.Platform.IPC.NamedPipeClient.ConnectAsync(CancellationToken cancellationToken)
        at Microsoft.Testing.Platform.DotnetTestConnection.AfterCommonServiceSetupAsync()
   ```

   `-532462766` = `0xE0434352`（CLR 未处理异常码被 MTP 透出）；Git Bash 侧 `$?` 报 `127`。
   注意关键词是 **`DotnetTestConnection`**：挂在「测试宿主连接 `dotnet test` 命令行」这一步，不是挂在测试执行或断言上。

2. **同进程内自建管道可用**：`pwsh` 里 `NamedPipeServerStream` + `NamedPipeClientStream` 互连返回 `PIPE_OK`。

3. **跨进程自建管道也可用**（这条是我新做的，比第 2 条更能说明问题）：两个独立 `pwsh` 进程，服务端 `WaitForConnection`、客户端 `Connect(3000)`，结果：

   ```
   --- 客户端（不同进程）---  CLI_OK
   --- 服务端 ---              SRV_WAITING pzd-x-69ec...  SRV_CONNECTED
   ```

   即：**这套环境并不禁止跨进程命名管道**。MTP 的握手被拒，是它与 `dotnet test` CLI 之间的那条管道（含其 ACL/身份要求）在受限执行环境里握不上，属环境特性。

4. 因此「改用 `dotnet test` 之外的跑法」得到的结果（直跑测试产物 `Total: 1, Failed: 0`）**只能证明测试逻辑与断言真绿，证明不了 `dotnet test` 链路可用**。两者不能互相替代，这一点写进遗留，别让后续票拿直跑结果当 `dotnet test` 通过的证据。

## 三、给团队的口径建议

- 票面里凡是「`dotnet test` 通过」，必须附 `总计 / 失败 / 成功` 三行原文与退出码；没有这三行的一律按「未运行」。
- 04 号票的 CI 验收里加一条：runner 上 `dotnet test Pzd.slnx` 退出码 0 **且** 输出含 `总计: ` 后跟大于 0 的数字，防止 CI 上也吃「0 用例 + 退出 0」的假绿。
- 「替代执行（直跑测试产物）」与「`dotnet test` 本体」在证据里分两行记，不要合并成一句「测试通过」。
