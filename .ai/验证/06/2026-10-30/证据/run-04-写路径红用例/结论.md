## 一、两条红用例（实测：`Total: 2, Errors: 0, Failed: 2`）

### 红 1｜分离实体更新不得抹掉创建审计字段（老登 high 1）

```csharp
var user = new ProbeUser { TenantId = 1, UserName = "张三" };
await db.Insertable(user).ExecuteCommandAsync(ct);

// 只带 Id / Version / UserName 的「分离实体」（真实场景：只加载了一部分列）
var patch = new ProbeUser { Version = user.Version, UserName = "张三-改" };
WithId(patch, user.Id);                       // Id 是 protected set，测试里用反射造
var failure = await PersistenceWriter.UpdateAsync(db, patch, CreateOptions(), ct);
Assert.Null(failure);

var createdBy = await database.QueryScalarAsync<long>($"SELECT CreatedBy FROM probe_user WHERE Id = {user.Id}", ct);
Assert.Equal(CurrentUser, createdBy);          // 现在拿到 0
Assert.True(createdAt.Year > 2000, …);         // 现在会被抹成 1900-01-01
```

失败原文：

```
Assert.Equal() Failure: Values differ
Expected: 7
Actual:   0
```

与老登探到的 `CreatedAt=1900-01-01 / CreatedBy=0` 一致。

### 红 2｜更新不得把整行搬到别的租户（老登 high 2）

```csharp
// 乙租户拿着同 Id、同 Version 的实体来更新
var foreign = new ProbeUser { Version = user.Version, TenantId = 2, UserName = "张三" };
WithId(foreign, user.Id);
var failure = await PersistenceWriter.UpdateAsync(db, foreign, CreateOptions(), ct);

var tenant = await database.QueryScalarAsync<long>($"SELECT TenantId FROM probe_user WHERE Id = {user.Id}", ct);
Assert.True(failure is not null, "跨租户更新应当被拒绝，但调用返回了成功");
Assert.Equal(1, tenant);
```

失败原文：`跨租户更新应当被拒绝，但调用返回了成功`。

这条我写得**对两种改法都成立**：加租户谓词（会返回冲突/失败）也好，SET 里排除 `TenantId`（`TenantId` 仍是 1、`failure` 为 null）也好——**注意后者会让第一条断言失败**。所以按哪种改法，把 `Assert.True(failure is not null, …)` 与 `Assert.Equal(1, tenant)` 二者留一个即可：

- 选「加租户谓词」：留 `Assert.True(failure is not null)`（并断言 `failure.Kind`）；
- 选「`TenantId` 不进 SET」：删掉 failure 断言，只留 `Assert.Equal(1, tenant)`。

请雨哥按你实际采用的方案选一种，别两条都留导致自相矛盾。

## 二、第三条 high（软删除强制点）：形状没定，我先不落用例

老登给的是二选一：**加唯一软删除入口**，或 **在 AOP 里拦 `DeleteByObject`**。两者对应的断言写法完全不同：

- 若走「入口 + 拦截 `Deleteable`」：`db.Deleteable(user).ExecuteCommandAsync()` 应**抛异常**（或走软删除），断言写成 `Assert.ThrowsAnyAsync`；
- 若走「唯一软删除入口」且 `Deleteable` 保持物理删：那要断言的是「业务代码里不存在 `Deleteable` 调用」，属静态检查（13 号票分层守卫的活），不该塞进集成测试。

所以我没有自作主张写，**请老何定形状后我十分钟内补上红用例**。顺手记一条：`SetColumns` 形态不写 `DeletedToken`（恒 0）导致随后同名重建撞 1062，这个不管选哪种改法都要有覆盖，用例形态取决于最终入口长什么样。
