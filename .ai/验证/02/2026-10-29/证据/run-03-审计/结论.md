## 2. 必须修

### high-1 `ssr: true` 违背 architecture §14.1（含 §1）

- 位置：[apps/web/react-router.config.ts:6](<E:/pzd/.worktree/02/apps/web/react-router.config.ts>) `ssr: true`（注释仍是模板原文「Server-side render by default」）；[apps/web/package.json](<E:/pzd/.worktree/02/apps/web/package.json>) 的 `@react-router/serve` 与 `start: react-router-serve`。
- 为什么错：architecture §1「React Router v7 framework mode，`ssr: false`（SPA）」、§14.1 表格同句。这不只是配置值，还是部署形态：§14.5 首选「前端 `build/client` 拷入 `Pzd.Api` 的 `wwwroot`，单容器同源」，§15.2 的新版本提示也依赖纯客户端构建产物。
- 实测证据：本审计构建后 `apps/web/build/` 下是 `client/` + `server/`，且 `build/client` **没有 `index.html`** —— SSR 形态，SPA 产物不存在。
- 修法（二选一）：① 改 `ssr: false`，去掉 `start`/`@react-router/serve` 依赖，复跑 `build --force` 后给出「`build/client/index.html` 存在」的证据；② 若确实要 SSR，须维护者拍板改 architecture.md，并按 `决策笔记 §1` 补笔记说明选 A 没选 B。

### high-2 `apps/web/Dockerfile` 与 `.dockerignore` 是模板残件，且已结构性失效

- 位置：[apps/web/Dockerfile:4,7,9,18,22](<E:/pzd/.worktree/02/apps/web/Dockerfile>)（`RUN npm ci`、`COPY ./package.json package-lock.json`）、[apps/web/.dockerignore:4](<E:/pzd/.worktree/02/apps/web/.dockerignore>)（引用不存在的 `README.md`）。

- 修法：本票直接删除这两个文件（属模板残留清理，不新增范围）；容器化交付留给 §15.4 的票。

### medium-1 turbo 缓存跨 worktree 共享，票面的 typecheck 证据不可判定

- 事实：审计侧在**全新 worktree** 里第一次跑 `pnpm typecheck` 就是 `cache hit, replaying logs`，turbo 打印 `Remote caching disabled, using shared worktree cache`。也就是说同一仓库其他 worktree 跑过的任务，这里能直接「绿灯回放」。
- 为什么错：票面「验证」里的 `pnpm typecheck` 片段不带 `--force`，在同一环境下无法区分「实跑」与「回放」；李总已发现 `pnpm test` 同款问题，本条把它扩到 typecheck，并给出「跨 worktree 共享」这个机制解释。
- 修法：票面三条 turbo 证据统一改成 `--force`（`build --force`、`test --force`、`typecheck --force`），并在交接里写一句「看到 `cache hit, replaying logs` 即判本次未运行」。建议老何把这句并进 04 票的 CI 断言。

### medium-2 「先跑红再转绿」没有证据

- 事实：票面称「先跑红（`Cannot find module '.../test'`）再实现转绿」，但 `.ai/验证/02/2026-10-29/` 下只有 `run-02-独立复核/`，无 run-01、无红跑日志。
- 为什么错：本项目把「先证红」当作测试有效性的证据（01 票就是这么做的），只有叙述没有日志等于没有证据。
- 修法：补一次红跑日志（`git stash` 或临时改掉断言后跑 `pnpm test --force`）放进 `证据/run-01/`，或把票面措辞降级为「未留存红跑日志」。

### medium-5 生成产物入库但没有 `.gitattributes`，每次构建后工作树必脏

- 事实：干净 worktree 里 `pnpm build --force` 之后 `git status` 立刻出现 ` M packages/api/src/generated/client.ts`；`git diff` 为空、字节对比内容一致，差异只是 LF 与 CRLF。
- 为什么错：`packages/api/src/generated/client.ts` 是入库的生成产物（票面已申报），生成脚本写 LF，Windows 检出按 autocrlf 写 CRLF，于是「干净 clone → 构建 → 工作树脏」成为默认结果；将来 CI 若做 `git diff --exit-code` 校验会直接失败。
- 修法：仓库加 `.gitattributes`（至少 `* text=auto eol=lf`，或对生成产物 `-text`），或由 28 号票改成生成物不入库；本票至少要把它写进遗留。
