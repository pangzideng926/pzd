## 三、⚠️ 复跑必须先 `--force`：默认 `pnpm test` 可能只是回放缓存

```
# 首次（未加 --force）
@workspace/api:test: cache hit, replaying logs 9e99cc3a015b5ee0
Tasks:    1 successful, 1 total
Cached:    1 cached, 1 total
TEST_EXIT=0
```

这一行意味着**测试进程没有被执行**，日志是 turbo 从上次成功结果重放的。退出码照样是 0、`pass 2 / fail 0` 照样出现，但它证明的是「同一份输入的缓存里存着一次通过」，不是「这次跑过了」。

强制实跑后才是真证据：

```
@workspace/api:test: cache bypass, force executing 9e99cc3a015b5ee0
@workspace/api:test: ✔ 从 openapi.json 生成 TS 客户端占位文件 (2.4577ms)
@workspace/api:test: ✔ openapi.json 缺 paths 时报错而不是静默生成空文件 (1.2605ms)
@workspace/api:test: ℹ pass 2 / fail 0 / duration_ms 62.5162
Cached:    0 cached, 1 total
```

**结论：两种跑法本票都是真绿**（强制实跑 2/2 通过），但**流程口径要补一条**：以后凡是要拿「测试通过」当验收证据，命令一律 `pnpm test --force`（或 `TURBO_FORCE=1`），日志里必须看到 `cache bypass, force executing` 或 `Cached: 0`，看到 `cache hit, replaying logs` 就判「本次未运行」，按 01 票那套假绿判据处理。建议老何把它并进 04 号票（仓库约定与 CI）——CI 里也不该吃缓存绿。

## 四、测试断言自查（不是空断言，但覆盖面要说清）

`packages/api/test/generate.test.mjs` 两个用例，我读过实现后确认断言有效、非同义反复：

1. `从 openapi.json 生成 TS 客户端占位文件`：写一份临时 spec（title `Pzd API`、path `/api/health`、version `0.0.0`）→ 跑 `generateClient` → 读产物断言含标题、含 `"/api/health"`、含版本号。断言值来自**输入的 spec**（独立来源），能真实捕捉「没读这份 openapi.json」这类退化。
2. `openapi.json 缺 paths 时报错而不是静默生成空文件`：`assert.throws(/paths/)`，是负向保护，方向正确。

**覆盖面风险（medium，记入后续票面口径）**：

- 根 `pnpm test` 实际只跑了 `packages/api` 一个包（`Tasks: 1 successful, 1 total`）。`apps/web`、`packages/ui`、`packages/realtime` 都没有 `test` 脚本，**web 侧零测试**。骨架阶段可以接受，但票面/交接里不能只写「`pnpm test` 通过」，要写「`pnpm test` 覆盖 packages/api 2 个用例，web 无测试」。
- 生成脚本里 `pathList` 排序、`apiPaths` 数组是否真的被写出，目前只由「含 `/api/health` 字样」间接覆盖，没有直接断言 `export const apiPaths`。28 号票换成 orval 时补，不用现在返工。

## 五、环境坑复核（雨哥提的两条，我逐条验了）

1. **pnpm 12 的 `allowBuilds` 映射写法**：`pnpm-workspace.yaml` 用的是
   ```yaml
   allowBuilds:
     esbuild: true
   ```
   `pnpm install` 后 esbuild postinstall 正常 `Done`、无 `ERR_PNPM_IGNORED_BUILDS`。雨哥说的「旧 `onlyBuiltDependencies` 会被解析但不生效」我没改配置去反证（会动实现），按他的结论接受，现有写法确实生效。
2. **`react-router dev` 只监听 IPv6 回环**：`netstat -ano | grep 5173` 实测只有
   ```
   TCP    [::1]:5173    [::]:0    LISTENING    16568
   ```
   没有任何 `127.0.0.1:5173 LISTENING`，因此 `curl 127.0.0.1:5173/` 与 `curl localhost:5173/` 都是 `000`——雨哥的判断成立，这是监听地址问题，不是页面渲染问题。
   补充一条他没提的：我这台 `curl -6 http://[::1]:5173/` 也是 `000`（无代理变量，`--noproxy '*'` 同样失败），说明本机 curl 的 IPv6 回环这条路不通。**因此唯一可靠访问方式是 `--host 127.0.0.1`**，这条应写进 03 号票的 README/开发说明，否则下一个人还会以为是服务没起来。
