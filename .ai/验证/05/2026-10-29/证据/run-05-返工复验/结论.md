## 三、一处措辞要改（不影响代码，影响后人判断）

票面与新公告的注释写着：**「若改成 record 主构造 + init 属性，`error with { Code = "坏码" }` 会绕过校验」**。这句作为「为什么选显式构造」的理由**不成立**，我做了编译 + 运行实测：

```csharp
public sealed record ErrorRecordStyle
{
    private readonly string _code = "";
    public string Code
    {
        get => _code;
        init
        {
            var segments = value.Split('.');
            if (segments.Length != 3 || segments.Any(s => s.Trim().Length == 0))
                throw new ArgumentException($"错误码格式非法：{value}");
            _code = value;
        }
    }
    public string Message { get; init; } = "";
}

var ok = new ErrorRecordStyle { Code = "Identity.User.NotFound", Message = "m" };
var bad = ok with { Code = "坏码" };     // 实测抛异常
```

实测输出（`record-with-probe.log`）：

```
构造成功：Identity.User.NotFound
WITH_BLOCKED：错误码格式非法：坏码
```

即：**校验放在 `init` 访问器里，`with` 同样会走校验、不会绕过。** trust 准确的表述应该是：

> record 主构造没有构造函数体，校验不能直接写在构造里，只能放进 `init` 访问器或静态工厂；显式构造 + get-only 属性是最省事且等价的写法。

为什么要纠这句：现在公告把「record 一定绕过校验」当既定事实写进冻结契约，将来有人改成「静态工厂 + 无校验 `init` 属性」时会以为自己是安全的——那才是真的漏洞。改一句话的成本远低于后面追一次越权构造。

**结论：代码选择（保留显式构造）是对的，理由要换。**

## 四、新发现（low，不阻塞）

`Result<T>.Success` 对引用类型允许传 `null`，且不报错：

```csharp
var result = Result<string>.Success(null!);
// 实测：IsSuccess == true，result.Value == null，取 Value 不抛
```

证据：`nullprobe.log`，探针用例通过（当时 `Total: 33, Failed: 0`），说明这是当前真实行为而不是我猜的。

两条出路，二选一写进票面即可：
- 在 `Result<T>.Success` 里 `ArgumentNullException.ThrowIfNull(value)`（但会挡住 `Result<int?>` 这类合法 null 值场景，要谨慎）；
- 或票面写明「引用类型允许成功的 null 值，调用方自行判空」，并补一条用例把这个契约钉住。

我倾向后者：本票是基类骨架，别在这一票引入过强约定；但必须写明，否则 06 之后每个调用方各猜一套。
