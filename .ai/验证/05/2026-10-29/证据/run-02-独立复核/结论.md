## 三、断言质量：我做了变异验证，发现一个真缺口

光看「24 全绿」不够——我关心的是这些用例能不能抓到实现退化。做法：在一次性 worktree 里改实现、跑测试、立即还原（`git status` 干净，未推任何提交）。

**变异 M1**：把 `ValueObject.Equals` 的类型守卫

```csharp
if (other is null || other.GetType() != GetType())   // 原实现
if (other is null)                                   // 变异后
```

结果：**`Total: 24, Failed: 0`，依然全绿**。

结论：`other.GetType() != GetType()` 这条分支**没有任何用例覆盖**。原因在 `值对象与不同类型的对象比较不相等` 这条用例——它比的是 `Money` 和 `string`，`string` 不是 `ValueObject`，走的是 `obj as ValueObject` 得到 `null` 的分支，压根没进「两个不同的 ValueObject 子类」的比较路径。也就是说：**两个分量完全相同、但类型不同的值对象现在应不相等，而这条约束没有任何测试守着**，将来有人把「类型不同即不相等」改掉，测试不会红。

**补丁用例（我已本地验证红绿均可复现）**：

```csharp
// TestTypes.cs 追加
internal sealed class MoneyTwin(decimal amount, string currency) : ValueObject
{
    public decimal Amount { get; } = amount;
    public string Currency { get; } = currency;
    protected override IEnumerable<object?> GetEqualityComponents()
    {
        yield return Amount;
        yield return Currency;
    }
}

// ValueObjectTests.cs 追加
[Fact]
public void 分量相同但类型不同的值对象不相等()
{
    var money = new Money(100m, "CNY");
    ValueObject twin = new MoneyTwin(100m, "CNY");

    Assert.False(money.Equals(twin));
    Assert.False(twin.Equals(money));
    Assert.NotEqual<ValueObject>(money, twin);
}
```

实测：正确实现下 `Total: 25, Failed: 0`；叠加 M1 变异后 `Failed: 1`、退出码 1，报错点正是这条新用例。**能证红的用例才算有效证据**。

「不可变」这条为什么算缺口而不是吹毛求疵：`ValueObject` 基类**在语言层面无法强制子类不可变**，靠的就是约定 + 用例示例。现在连一条「值对象不得带 public setter」的示例都没有，新写值对象带 `set` 也不会被拦。建议补一条反射用例（能防新代码引入 setter，抓不到真·运行期可变场景——这层局限要在用例注释里写明）：

```csharp
[Fact]
public void 值对象的属性不对外暴露setter()
{
    var settable = typeof(Money).GetProperties()
        .Where(p => p.SetMethod is { IsPublic: true })
        .Select(p => p.Name)
        .ToArray();

    Assert.Empty(settable);
}
```

## 五、剩余风险与建议（均不阻塞合入）

1. **medium｜跨类型不相等无覆盖**：见 §三，已在上面给出了经验证的用例，请锋哥落进 `ValueObjectTests.cs` + `TestTypes.cs`（只动测试文件，不碰实现）。
2. **medium｜AC2「不可变」无断言**：见 §四。
3. **low｜`Result<T>.Failure(null)` 未覆盖**：现有用例只测了非泛型 `Result.Failure(null)`；`Result<T>.Failure` 用的是 `new` 静态方法，独立实现了一条 `ArgumentNullException` 校验，没被任何用例守到。
4. **low｜`Error` 空白段未覆盖**：实现用 `IsNullOrWhiteSpace` 判段，但用例里只有空段（`Identity..NotFound`），没有纯空白段（`"Identity.   .NotFound"`）。要么补一条 `[InlineData("Identity. .NotFound")]`，要么把实现降成 `Length > 0` 以免文档与行为不一致。
5. **info｜`AggregateRoot` 去重是按引用而非按值**：`Raise` 用 `ReferenceEquals` 去重，两个"值相同但不同实例"的事件会被收集两条。这与票面「同一个事件实例重复添加只保留一次」的措辞一致；但这是 08 号票投递幂等的前提假设，建议在 08 票面显式写一句「同值不同实例视为两个事件」，否则后面容易争。
6. **info｜S4 只有正例没有反例**：票面要求「每个 seam 至少一条正例与一条反例」，S4 只有「不含 SqlSugar/AspNetCore」一条断言。属自证型 seam，可以接受，但若要严格对齐票面，可加一条「引用集合非空且包含 System.Runtime」之类的反例锚点。
7. **环境项**：`dotnet test` 本体仍需在无管道限制环境补跑一次（与 01 同因，三家 Bot 环境一致失败，属环境共性）。
