## 一、high｜`Error` 公告形状与实现不一致：编译证据

探针（写完即删，未提交）：

```csharp

source with { Message = "m2" }                          // 公告是 record，预期可用

```

`dotnet build tests/Pzd.SharedKernel.UnitTests` 结果：**退出码 1**，三条错误原样如下：

```
error CS1739: “Error”的最佳重载没有名为“Code”的参数
error CS0200: 无法为属性或索引器“Error.Message”赋值 - 它是只读的
error CS0029: 无法将类型“Pzd.SharedKernel.Error”隐式转换为“(string Code, string Message)”
```

对应关系：`CS1739` = 无 `Code`/`Message` 参数名（实际参数名是 `code`/`message`），`CS0200` = 属性只读、`with` 不可用，`CS0029` = 没有 `Deconstruct`。

## 三、我这边同意的另外两条（附具体改法）

1. **`[InlineData("")]` 的 `Assert.Contains(invalidCode, …)` 是恒真断言**：`Assert.Contains("", 任意字符串)` 永远成立。改法二选一，别留：
   ```csharp
   // 方案 A：空串单独一条，只断言异常类型
   [Fact]
   public void 空错误码抛ArgumentException() =>
       Assert.Throws<ArgumentException>(() => new Error("", "随便"));

   // 方案 B：Theory 内条件断言
   if (invalidCode.Length > 0)
       Assert.Contains(invalidCode, exception.Message, StringComparison.Ordinal);
   ```
   注意「纯空白段」那三条（`"Identity. .NotFound"` 等）不受影响，它们的 `Contains` 是真断言。
2. **`状态只能通过方法变更` 名不副实**：它只证明 `ChangeNumber` 生效，没证明「只能」。改法：`Assert.Equal("SO-002", order.Number)` 之外，补一条反射断言 `typeof(Order).GetProperty("Number").SetMethod.IsPublic == false`（对测试类型 `Order` 有效），或直接把用例改名为 `变更方法生效`，别让名字承诺它没测的东西。
