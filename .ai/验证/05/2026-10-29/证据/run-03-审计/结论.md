## 2. 必须修

### high-1 `Error` 与票面「冻结的公开签名」不一致，06 会按错的契约开工

- 位置：[src/Pzd.SharedKernel/Error.cs:13,27,29](<E:/pzd/.worktree/05/src/Pzd.SharedKernel/Error.cs>) 对票面 `docs/work/cross-cutting/tickets/05-shared-kernel.md` 的冻结段（`public sealed record Error(string Code, string Message);`）。
- 为什么错：实现是显式构造函数 + `{ get; }` 属性，因此**没有 `Deconstruct`、不支持 `with`、命名实参 `new Error(Code: …, Message: …)` 编译失败**。而票面写死「合入前必须冻结公开签名（此后只增不改），06 号票按这份签名并行开工」。公告与代码不一致，等于冻结失效——这正是这张票要防的返工。
- 修法（二选一，改完必须重新公告一次）：① 把实现改成主构造函数形式 `public sealed record Error(string Code, string Message)`，校验移进属性 `init` 访问器或静态工厂（注意：主构造形式的校验不能在构造体里抛，要想清楚放哪）；② 保留现实现的校验方式，把冻结段的签名改成实际形状并明确写「无 `Deconstruct`、不支持 `with`、参数字名 `code`/`message`」，重新公告 06、09。

### medium-1 `AggregateRoot.DomainEvents` 能绕过 `Raise`/`ClearDomainEvents`

- 位置：[src/Pzd.SharedKernel/AggregateRoot.cs:19](<E:/pzd/.worktree/05/src/Pzd.SharedKernel/AggregateRoot.cs>)：`=> _domainEvents;` 直接返回内部 `List<IDomainEvent>`。
- 为什么错：`IReadOnlyList<T>` 只是接口约束，调用方 `(List<IDomainEvent>)aggregate.DomainEvents` 就能强转后增删，绕过唯一入口与清空语义。基类被所有模块继承，冻结之后再改要协调 06 及全部消费方。
- 修法：`=> _domainEvents.AsReadOnly();`（签名不变、零破坏），或内部改 `ReadOnlyCollection<IDomainEvent>` 并缓存实例。

### medium-2 注释与实现相反

- 位置：[src/Pzd.SharedKernel/ValueObject.cs:9](<E:/pzd/.worktree/05/src/Pzd.SharedKernel/ValueObject.cs>) 写「分量顺序无关但两侧必须一致」，实现是 `SequenceEqual`（**有序**比较）。
- 为什么错：按注释理解，两个分量顺序不同的值对象应当相等；按代码则不相等。这类反向注释比没注释更危险，会让人写出错的值对象。
- 修法：把注释改成「分量按顺序逐项比较，两侧顺序必须一致」，或真做成顺序无关（不推荐，会掩盖分量顺序错误）。
