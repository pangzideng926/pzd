# 05 附：`with` 能否绕过校验——三种写法的对照实验

- 复核人：PZD-测试Bot（李总）
- 时间：2026-10-29 22:2x（Asia/Shanghai）
- 缘起：我前一轮说「record + init 访问器校验，`with` 也被拦住（`WITH_BLOCKED`）」，锋哥说他实测「主构造 + init 属性带校验，`with` 绕过（`WITH_BYPASSED`）」。两边结论相反，我拆成三种写法一次测清。

## 一、结论：两边都对，区别在**校验写在哪**，不在「class 还是 record」

| 写法 | 构造非法码 | `with { Code = "坏码" }` | 说明 |
|---|---|---|---|
| A 主构造 + 校验在**属性初始化器**（`public string Code { get; init; } = Guard.Code(Code);`） | 抛 | **WITH_BYPASSED**，拿到 `坏码` | 属性初始化器只在主构造路径跑一次，`with` 走复制构造、不重跑 |
| B 主构造 + 校验在 **`init` 访问器**（`private readonly string _code; init => _code = Guard.Code(value);`） | 抛 | **WITH_BLOCKED**，抛 `ArgumentException` | `with` 会重新调 `init` 访问器 |
| C 显式构造 + get-only 属性（05 现实现） | 抛 | **编译不过**（`CS0200` 只读属性） | 连 `with` 的语法都没有 |

实测输出（`with-variants.log`）：

```
A 构造(合法): 构造成功 A.B.C
A 构造(非法): 构造就被拦 错误码格式非法：坏码
A 主构造+属性初始化器校验: WITH_BYPASSED 得到 坏码
B 构造(合法): 构造成功 A.B.C
B 构造(非法): 构造就被拦 错误码格式非法：坏码
B 主构造+init 访问器校验: WITH_BLOCKED 错误码格式非法：坏码
```

## 二、给票面的精确措辞（建议直接替换现在那句）

> record 主构造的参数校验只在构造那一次生效；`with` 走复制构造，不会重跑属性初始化器，因此**把校验写在属性初始化器里会被 `with` 绕过**。要让 `with` 也受约束，校验必须放进 `init` 访问器（写法更绕，且属性不再是纯只读）。综合成本，本票选显式构造 + get-only 属性：校验写一次、`with` 直接编译不过。

要点：现在票面那句「改成 record 主构造 + init 属性就会绕过校验」把三种情形混成了一句，06/09 照字面理解会得出「record 天生不安全」的错误结论；按上表写成「取决于校验位置」才是可执行的事实。
