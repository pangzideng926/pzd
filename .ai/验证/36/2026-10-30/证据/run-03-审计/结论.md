## 三、发现

### high（必须修）

**1. `tests/Pzd.IntegrationTests/Fixtures/MySqlServerFixture.cs:48` —— 容器不可用时「明确错误」从未生效**

```csharp
_source = MySqlSource.Container;
_container = new MySqlBuilder(ImageTag).Build();   // ← 在 try 外面
try
{
    await _container.StartAsync();
}
catch (Exception exception) { throw new InvalidOperationException("...请安装并启动 Docker，或设置环境变量...", exception); }
```

- **为什么错**：`Build()` 内部会 `Validate()` 探测 Docker 端点，容器不可用时在这里就抛 `DockerUnavailableException`，压根进不到 `catch`。票面步骤 2 明写「两者都不可用时给出明确错误」，实测拿到的是 Testcontainers 的英文栈。
- **实测**：我移走外部连接串、本机无 Docker 跑 `-class SmokeTests`，`grep "请安装并启动"` **零命中**；只有 `DockerUnavailableException: Docker is either not running or misconfigured`。李总先发现，我复核成立。
- **修改建议**：把 `Build()` 挪进 `try`：

```csharp
Container = MySqlSource.Container;
try
{
    _container = new MySqlBuilder(ImageTag).Build();
    await _container.StartAsync();
}
catch (Exception exception) when (exception is not OperationCanceledException)
{
    throw new InvalidOperationException(
        $"容器不可用（镜像 {ImageTag}）。请安装并启动 Docker，或设置环境变量 {ExternalConnectionStringVariable}"
        + $"（或写入仓库根 .local/{LocalConnectionStringFileName}）指向一个能建库的真 MySQL。", exception);
}
```
- **验法**：改完再移走 `.local` 文件跑一次，报错里必须能看到那句中文。

### medium

**2. `MySqlServerFixture.InitializeAsync` 的来源优先级与 AC-04 相反，且票面内部自相矛盾**

- 代码行为：**配了外部连接串就直接走外部**，完全不看容器是否可用：
  ```csharp
  var external = ReadConfiguredConnectionString();
  if (external is not null) { Source = External; ... } else { Source = Container; ... }
  ```
- AC-04 原文：「**容器可用时按 `mysql:8.4` 起库**；容器不可用时回落外部真库」——顺序是容器优先。
- 票面「环境与替代方案」段却又写：「1. 容器可用 → 按票面固定 tag 起库；2. **调用方给出外部连接串** → 回落外部真库」——按这段读，配了就回落，跟代码一致，跟 AC-04 相反。
- 类注释也自相矛盾：「来源优先容器（票面固定 `mysql:8.4`）；设置了外部连接串时走外部真库」。
- **为什么错**：后果很具体——只要 CI 或任何机器同时具备 Docker 和外部连接串，**容器路径永远不执行**，AC-04 的容器分支和 AC-05 的「有容器环境复核一次」就成了纸面条款，`mysql:8.4` 与 `8.0.46` 的差异永远发现不了。
- **修改建议**（二选一，别两头都不动）：① 代码改成容器优先：先探测 Docker 可用性，可用则起容器，不可用再回落外部，外部也没有才抛上面那条明确错误；② 承认工程上「显式配置优先」更实用（本机每次跑不必等容器探测超时），那就把 AC-04 改成「**显式配置外部连接串时优先**；未配置时按 `mysql:8.4` 起容器」，并在遗留写明「容器路径只在未配置外部串的环境执行，CI 若有外部串则容器路径不覆盖」。改哪条都要同步改类注释和「环境与替代方案」段。

**3. `MySqlServerFixture.DropDatabaseAsync` 缺库名前缀护栏，而账号带全局 `DROP`**

- 现状：`DROP DATABASE IF EXISTS \`{name}\``，`name` 直接拼进 SQL，没有任何前缀校验。
- 实测权限：`SHOW GRANTS` → `GRANT CREATE, DROP ON *.*` 与 `GRANT ALL PRIVILEGES ON \`pzd\_test\_%\`.*`。**全局**那条意味着这个账号能对 `pzd_master` 建表删表。
- **为什么错**：`CREATE, DROP ON *.*` 是「要建随机库名」逼出来的，无法只授给不存在的库（MySQL 的已知限制），所以真正的防线必须落在代码里。现在只要有人给 `DropDatabaseAsync` 传错名字（比如 03 那个 `pzd-master` / `pzd_master` 混淆，或将来某个测试写错库名），就会静默删掉一个真实库。06–32 全都要用这套 fixture，风险面会一直放大。
- **修改建议**（2 行成本）：

```csharp
internal async ValueTask DropDatabaseAsync(string name, CancellationToken cancellationToken)
{
    if (!name.StartsWith(DatabaseNamePrefix, StringComparison.Ordinal))
    {
        throw new InvalidOperationException($"拒绝删除非测试库：{name}（必须以 {DatabaseNamePrefix} 开头）");
    }
    await ExecuteOnServerAsync($"DROP DATABASE IF EXISTS `{name}`", cancellationToken);
}
```
  同时把 `"pzd_test_"` 提成 `private const string DatabaseNamePrefix = "pzd_test_";`，`CreateDatabaseAsync` 复用，并在注释里写明「这个前缀是授权前提，别随手改」。
