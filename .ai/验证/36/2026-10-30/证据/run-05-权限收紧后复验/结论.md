## 二、权限收紧后 fixture 还能不能建库（老登也提了这条）

以 `pzd_test` 实际演练 fixture 的两次操作：

| 操作 | 结果 |
|---|---|
| `CREATE DATABASE pzd_test_probe_lz CHARACTER SET utf8mb4` | 成功 |
| `DROP DATABASE pzd_test_probe_lz` | 成功 |
| `CREATE DATABASE pzd_probe_no_prefix` | **`ERROR 1044` Access denied to database** |
| `DROP DATABASE IF EXISTS pzd_probe_guard_nonexistent` | **`ERROR 1044` Access denied to database** |

结论两条：
1. **收紧后 fixture 的建库/删库路径仍然可用**（`pzd_test_%` 的 `ALL PRIVILEGES` 覆盖建库），36 那三条绿灯在新权限下不受影响；
2. 我上一轮那条「传错库名就能删掉 `pzd_master`」的**破坏路径已被权限堵死**（非前缀名直接 1044）。护栏仍该加，理由不变：权限是环境状态，代码是长期合同；而且护栏能让错误在代码层说清原因，不用去猜 MySQL 的 1044/1142。

## 三、与转述不符：`pzd_master` 不是空库，有 15 张 Quartz 表

张一一转述是「`pzd_master` 空库已建好（utf8mb4），等 17 号票做迁移建表」。我用 `pzd_dev` 账号实测（`information_schema`）：

```
pzd_master	utf8mb4          ← 字符集正确
pzd_master 表数量 = 15        ← 不是 0
```

表清单全部是 **Quartz.NET 调度器 schema**：

```
qrtz_blob_triggers 0    qrtz_calendars 0         qrtz_cron_triggers 1*
qrtz_execution_history 0 qrtz_fired_triggers 0   qrtz_job_details 0
qrtz_job_status 0        qrtz_locks 2*           qrtz_misfire_history 0
qrtz_paused_job_grps 0   qrtz_paused_trigger_grps 0  qrtz_scheduler_state 0
qrtz_simple_triggers 0   qrtz_simprop_triggers 0 qrtz_triggers 1*
```

（`*` 为 `TABLE_ROWS` 非零：`qrtz_cron_triggers` 1、`qrtz_triggers` 1、`qrtz_locks` 2。`TABLE_ROWS` 对 InnoDB 是估算值，但「有调度记录」这个方向可信；要精确行数需 `COUNT(*)`。）

也就是说：**某个环节已经在 `pzd_master` 里跑过 Quartz 建表并排过一个作业**。这不是我做的（我只建删过 `pzd_test_*` 与 `pzd_t_probe` 立即清理），来源应是 03 号票的调度器接入或更早的人工探测。

影响与需要拍板的事：
1. **17 号票（迁移建表）不能按「空库」假设写**。要么把这些 `qrtz_*` 表纳入迁移管理，要么在迁移前显式重置 `pzd_master`，二选一必须写进 17 票，否则第一次 `dotnet ef`/迁移就会撞「表已存在」或产生 schema 漂移。
2. 这几张表有活数据（`qrtz_locks` 2 行、触发器 1 条），说明可能有调度器**仍在运行**，重置前要先确认没有进程在连。
3. 谁建的、什么时候建的，建议 03 认领人（旺总）在票面留一句，别让 17 认领人凭空猜。

我只做了只读查询与自建探针库的建删（`pzd_t_probe`，用完 `DROP`，复查 `pzd_t%` 为 **0**），没有动 `pzd_master` 的任何表。

## 四、`pzd_dev` 授权与 DDL 能力（顺带核）

```
GRANT USAGE ON *.* TO `pzd_dev`@`localhost`
GRANT ALL PRIVILEGES ON `pzd_master`.* TO `pzd_dev`@`localhost`
GRANT ALL PRIVILEGES ON `pzd_t_%`.* TO `pzd_dev`@`localhost`
```

- 没有 `ON *.*` 全局权限，符合老何「两个账号分开、都不给全局」的口径；
- 在 `pzd_t_%` 上实测建库 → 建表 → 插入 → 查询 → 删库全部成功，DDL 能力确实具备；
- 探针库已清理，`pzd_t%` 复查 0。
