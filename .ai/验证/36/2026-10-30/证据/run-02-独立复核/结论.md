## 三、⚠️ medium 缺口：好意提示语在最常见失败路径上根本不出现

上面那次缺配置失败，报错是 Testcontainers 原始的：

```
DotNet.Testcontainers.Builders.DockerUnavailableException : Docker is either not running or misconfigured.
...
tests\Pzd.IntegrationTests\Fixtures\MySqlServerFixture.cs(48,0): at MySqlServerFixture.InitializeAsync()
```

而 `MySqlServerFixture.cs` 里精心写的那句操作指引——

> 「容器不可用（镜像 mysql:8.4）。请安装并启动 Docker，或设置环境变量 `PZD_TEST_MYSQL_CONNECTION`（或写入仓库根 `.local/mysql-test-connection.txt`）指向一个能建库的真 MySQL」

**没有出现**。原因是 `try/catch` 只包住了 `StartAsync()`，而 `new MySqlBuilder(ImageTag).Build()` 在 `try` 之外（第 48 行），Docker 不可用时 `Build()` 内部 `Validate()` 就先抛了，压根到不了 `StartAsync`。

影响：06 及之后任何人第一次在本机跑集成测试（没 Docker、没配连接串），看到的是 Docker 的原始英文报错，得自己摸索；这段本可以省掉的排查时间每次都白花。

**修法（一行级）**：把 `Build()` 挪进 `try`，或整个分支包进 `try/catch`：

```csharp
try
{
    _container = new MySqlBuilder(ImageTag).Build();   // 挪进来
    await _container.StartAsync();
}
catch (Exception exception)
{
    throw new InvalidOperationException($"容器不可用（镜像 {ImageTag}）……", exception);
}
```

**验证方式**：改完后同样移走 `.local` 文件再跑一次，报错里必须能看到那句中文指引。

## 四、low 项（不阻塞，建议写进票面）

1. **字符集断言的判别力**：现有 `独立库建表插入后能查回中文原文` 用的是「张三」（3 字节），utf8mb3 库里同样能存能取——我实测 `utf8mb3 + 张三` 退出码 0。不过另一条 `库默认字符集是utf8mb4` 直接断言 `information_schema` 的 `DEFAULT_CHARACTER_SET_NAME`，所以 **utf8mb3 退化整体仍会被抓到**，这两条组合是有效的。
   补强建议：往第一条里加一个 4 字节字符（如 U+1F642）就能让「插入路径也是 4 字节安全的」单独成立。实测对照：
   - `utf8mb4 + U+1F642` → 存成 `F09F9982`，退出码 0
   - `utf8mb3 + U+1F642` → `ERROR 1366 (HY000): Incorrect string value: '\xF0\x9F\x99\x82'`，退出码 1
2. **库名前缀是授权前提**：`pzd_test` 账号只对 `pzd_test_%` 有权限（我探针时用了 `pzd_chk_*` 直接吃 `ERROR 1142 INSERT command denied`）。所以 `CreateDatabaseAsync` 里的 `"pzd_test_"` 前缀不能随手改，改了本机会全红。这属于「看起来无害其实有依赖」的常量，建议在 fixture 注释里点一句。
3. **容器路径（`mysql:8.4`）确实未验证**：本机无 Docker，只能记「外部真库路径通过、容器路径未运行」。审计不要按「两种来源都验过」处理，锋哥这条记录准确。
4. **`dotnet test` 本体仍是环境性未运行**：`Total: 0` + 命名管道拒绝，与本轮其他票一致，证据均来自直跑 exe，按四项口径记。
