## 一、失败用例（可复现，无破坏性）

```csharp
public sealed class DropGuardProbe(MySqlServerFixture fixture) : IClassFixture<MySqlServerFixture>
{
    [Fact]
    public async Task 传非前缀库名时必须拒绝销毁()
    {
        // 名字故意不存在，Drop 无害；只验「有没有护栏」
        var db = new TestDatabase("pzd_probe_guard_nonexistent", string.Empty, fixture);

        await Assert.ThrowsAnyAsync<Exception>(() => db.DisposeAsync().AsTask());
    }
}
```

实跑结果（`8ca97a9`）：

```
Total: 1, Errors: 0, Failed: 1     [exit 1]
    Pzd.IntegrationTests.DropGuardProbe.传非前缀库名时必须拒绝销毁 [FAIL]
      Assert.ThrowsAny() Failure: No exception was thrown
```

**没有护栏，确认。** `TestDatabase` 的构造是公开的（主构造），所以任何代码都能 `new TestDatabase("pzd_master", …, fixture)` 再 `DisposeAsync()`，直接执行 `DROP DATABASE IF EXISTS \`pzd_master\``。

我**故意没有执行** `pzd_master` 那一版——只跑了不存在的名字，证明「任意库名都会被执行」。这类验证必须用无破坏性的等价输入，不能拿真库试刀。

## 二、权限现状实测（决定这条的严重度，别估）

`SHOW GRANTS FOR CURRENT_USER()`（`pzd_test@localhost`）：

```
GRANT CREATE, DROP ON *.* TO `pzd_test`@`localhost`
GRANT ALL PRIVILEGES ON `pzd_test\\_test\\_%`.* TO `pzd_test`@`localhost`
```

即：**全局 `CREATE, DROP` 还在，老何那三条 `REVOKE` 还没跑。** 所以此刻「一次传错库名就删掉 `pzd_master`」是真实可达的破坏，不是理论风险。

补充一个校准：用户跑完
```sql
REVOKE ALL PRIVILEGES ON *.* FROM 'pzd_test'@'localhost';
GRANT ALL PRIVILEGES ON `pzd_test_%`.* TO 'pzd_test'@'localhost';
```
之后，`pzd_test` 就没有全局 DROP 了，误传 `pzd_master` 会因权限不足失败——**爆破半径自然缩小**。但护栏仍然该加，理由两条：
1. 权限是环境状态，代码是长期合同；某天有人为省事把全局权限加回来，代码里那句前缀校验是唯一防线；
2. 前缀校验能把「传错名字」变成立刻失败并指出原因，而不是靠 MySQL 报 `1142` 让人猜。

## 三、我自己的一个失误（认领）

服务端那两个残留探测库（`pzd_chk_mb4` / `pzd_chk_mb3`）是**我**建的：我做字符集判别力实验时第一版用了 `pzd_chk_*` 前缀，INSERT 被授权拒掉（`ERROR 1142`），而我的清理语句只 DROP 了第二版改名的 `pzd_test_chk_*`，前一版漏了。老登审计时发现并清掉，现在实测 `pzd_test_%` 残库 **0 个**、`pzd%` 只剩 `pzd_master`。

以后我的规矩：**探针库当场 DROP，且命名一律带 `pzd_test_` 前缀**（顺便说，非前缀名现在会直接吃 `1142`，不是好用的探针名），并在证据文件里写清「已清理」。
